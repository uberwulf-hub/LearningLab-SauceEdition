@task t01 | Running systems | 15 | server1
Nobody knows the root password of server1. Interrupt the boot process of server1 and set the root password to `{rootpw}`. SELinux must stay enforcing and the machine must boot normally afterwards.
@check server1 | root can log in with the new password
certlab-check password root '{rootpw}'
@check server1 | the machine boots normally and SELinux is enforcing
certlab-check booted && test "$(getenforce)" = Enforcing
@solution server1
#reset
#key e
#key Down Down Down End
#type  rd.break
#key Ctrl+X
mount -o remount,rw /sysroot
chroot /sysroot
echo '{rootpw}' | passwd --stdin root
touch /.autorelabel
exit
exit
#password {rootpw}
@explain
At the boot menu press e, add rd.break to the end of the line that starts with linux, and boot with Ctrl+X. The boot stops in the initramfs, before the real root file system is used: it is mounted read-only on /sysroot. Remount it read-write, chroot into it so that passwd changes the right /etc/shadow, set the password, and create /.autorelabel. No SELinux policy is loaded at that point, so the new shadow file has no label; the relabel at the next boot fixes it. Forget it and nobody can log in with SELinux enforcing. Two exits leave the chroot and then the initramfs shell, and the boot continues.
@endtask

@task t14 | Shell scripts | 20 | server1
Write the script /usr/local/bin/{script}. It takes one or more folder names as arguments. For each argument it prints one line: `NAME: N files`, where N is the number of regular files directly in that folder (not in its subfolders), or `NAME: not a folder` when the argument is not a folder. Run without arguments, it prints `Usage: {script} FOLDER...` and exits with status 2.
@check server1 | without arguments: the usage line and exit status 2
out=$(/usr/local/bin/{script} 2>&1); rc=$?; test $rc -eq 2 && echo "$out" | grep -q "Usage: {script} FOLDER"
@check server1 | it counts only the files directly in a folder
mkdir -p /tmp/gr1/sub; touch /tmp/gr1/a /tmp/gr1/b /tmp/gr1/c /tmp/gr1/sub/d; /usr/local/bin/{script} /tmp/gr1 | grep -qx '/tmp/gr1: 3 files'
@check server1 | several arguments, and a name that is not a folder
mkdir -p /tmp/gr2; touch /tmp/gr2/x; out=$(/usr/local/bin/{script} /tmp/gr2 /tmp/nothing-here 2>&1); echo "$out" | grep -qx '/tmp/gr2: 1 files' && echo "$out" | grep -qx '/tmp/nothing-here: not a folder'
@solution server1
cat > /usr/local/bin/{script} <<'EOF'
#!/bin/bash
if [ $# -eq 0 ]; then
    echo "Usage: {script} FOLDER..."
    exit 2
fi
for d in "$@"; do
    if [ -d "$d" ]; then
        n=$(find "$d" -maxdepth 1 -type f | wc -l)
        echo "$d: $n files"
    else
        echo "$d: not a folder"
    fi
done
EOF
chmod +x /usr/local/bin/{script}
{script} /etc /nowhere
@explain
"$@" expands to all the arguments, each one kept whole even if it contains spaces, and for d in "$@" walks through them. $(...) captures a command's output into a variable: find -maxdepth 1 -type f lists only the regular files at the top level, and wc -l counts the lines. [ -d NAME ] is true for a folder. Do not forget the #! line and chmod +x.
@endtask

@task t20 | Deploy and maintain | 15 | server2
On server2:
- Create a systemd service `{tname}.service` that writes the output of `df -h` into /var/log/{tname}.txt, and a timer `{tname}.timer` that starts it every {mins} minutes (minute 0, {mins}, ... of every hour). The timer must be active and start at boot.
- With at, schedule a one-time job for 10:00 on 2026-03-{atday} that runs `logger "{tname} at job"`.
@check server2 | the timer is enabled and active
systemctl is-enabled {tname}.timer && systemctl is-active {tname}.timer
@check server2 | the timer runs every {mins} minutes
systemctl cat {tname}.timer | grep -Eq '^OnCalendar=.*:0?0/{mins}([^0-9]|$)'
@check server2 | the service writes the report
rm -f /var/log/{tname}.txt; systemctl start {tname}.service; grep -q Filesystem /var/log/{tname}.txt
@check server2 | the at job is queued for 10:00 on March {atday}
atq | grep -q 'Mar {atday} 10:00:00 2026' && for j in $(atq | awk '{print $1}'); do at -c $j | grep -q '{tname} at job' && exit 0; done; exit 1
@solution server2
cat > /etc/systemd/system/{tname}.service <<'EOF'
[Unit]
Description=Write a disk usage report

[Service]
Type=oneshot
ExecStart=/bin/sh -c 'df -h > /var/log/{tname}.txt'
EOF
cat > /etc/systemd/system/{tname}.timer <<'EOF'
[Unit]
Description=Disk usage report every {mins} minutes

[Timer]
OnCalendar=*:00/{mins}

[Install]
WantedBy=timers.target
EOF
systemctl daemon-reload
systemctl enable --now {tname}.timer
systemctl list-timers {tname}.timer
echo 'logger "{tname} at job"' | at 10:00 2026-03-{atday}
atq
@explain
A timer starts the service with the same name. OnCalendar=*:00/{mins} means every hour, starting at minute 0 and then every {mins} minutes (systemctl list-timers shows when it fires next). The timer, not the service, is enabled: WantedBy=timers.target starts it at boot. A Type=oneshot service runs its command and ends. at reads the commands from standard input; atq lists the queue and at -c N shows a job's commands. at jobs are kept in /var/spool/at and survive a reboot.
@endtask
