@task t03 | Networking | 15 | server2
Give server2's connection enp1s0 a static IPv6 setup as well: the address {p6}::12/64 with the IPv6 gateway {p6}::1. The IPv4 settings must stay static as they are now (192.168.50.12/24, gateway and DNS 192.168.50.254), so that server1 can still reach server2. The settings must survive a reboot.
@check server2 | the connection uses manual IPv6 with the address and gateway
test "$(nmcli -g ipv6.method con show enp1s0)" = manual && nmcli -g ipv6.addresses con show enp1s0 | grep -q '{p6}::12/64' && test "$(nmcli -g ipv6.gateway con show enp1s0)" = '{p6}::1'
@check server2 | after the reboot both addresses are active on enp1s0
ip -6 -br addr show enp1s0 | grep -q '{p6}::12/64' && ip -4 -br addr show enp1s0 | grep -q '192\.168\.50\.12/24'
@check server2 | IPv4 is still static with the lab gateway
test "$(nmcli -g ipv4.method con show enp1s0)" = manual && test "$(nmcli -g ipv4.gateway con show enp1s0)" = 192.168.50.254
@check server1 | server1 still reaches server2
ping -c 1 -W 2 192.168.50.12 >/dev/null
@solution server2
nmcli -g ipv4.method,ipv4.addresses con show enp1s0

@explain
Look before you change: the IPv4 side is already manual, so leave it alone. For IPv6, ipv6.method manual goes together with ipv6.addresses (the /64 is part of the address) and ipv6.gateway. nmcli con mod only changes the saved profile; nmcli con up applies it now. Changing ipv4.method or the IPv4 address by mistake is the classic way to lose the machine in the middle of an exam, so read the current values with nmcli -g first.
@endtask

@task t04 | Local storage | 20 | server2
On server2, create a partition on /dev/vdb and use it for a new volume group `{vgweb}`. In it create the logical volume `{lvweb}` of {lvsize} MiB, format it with xfs, and mount it on /srv/{site} at every boot. In /etc/fstab use the file system's UUID, not the device name.
@check server2 | {vgweb}/{lvweb} is {lvsize} MiB
test "$(lvs --noheadings --units m -o lv_size {vgweb}/{lvweb} | tr -d ' ')" = "{lvsize}.00m"
@check server2 | fstab mounts the UUID of {lvweb} on /srv/{site}
u=$(blkid -s UUID -o value /dev/{vgweb}/{lvweb}); test -n "$u" && grep -Eq "^UUID=\"?$u\"?[[:space:]]+/srv/{site}/?[[:space:]]+xfs" /etc/fstab
@check server2 | after the reboot xfs from {lvweb} is mounted on /srv/{site}
test "$(findmnt -n -o FSTYPE /srv/{site})" = xfs && test "$(findmnt -n -o UUID /srv/{site})" = "$(blkid -s UUID -o value /dev/{vgweb}/{lvweb})"
@solution server2
parted -s /dev/vdb mklabel gpt
parted -s /dev/vdb mkpart web 1MiB 1025MiB
parted -s /dev/vdb set 1 lvm on
pvcreate /dev/vdb1
vgcreate {vgweb} /dev/vdb1
lvcreate -n {lvweb} -L {lvsize}M {vgweb}
mkfs.xfs /dev/{vgweb}/{lvweb}
mkdir -p /srv/{site}
blkid /dev/{vgweb}/{lvweb}
echo "UUID=$(blkid -s UUID -o value /dev/{vgweb}/{lvweb}) /srv/{site} xfs defaults 0 0" >> /etc/fstab
systemctl daemon-reload
mount -a
findmnt /srv/{site}
@explain
blkid shows the UUID that mkfs wrote into the file system. blkid -s UUID -o value prints just the value, so $(...) can put it straight into the fstab line and nothing is typed wrong. A UUID belongs to the file system, not to the device name, so it stays right when disks are added or found in another order. mount -a tests the new line at once: a typo found now is better than a machine that stops in emergency mode at the grader's reboot.
@endtask

@task t05 | Security | 20 | server2
Install the Apache web server on server2. It must listen on TCP port {port} only (not on 80) and serve the folder /srv/{site}/html, which holds a file index.html with the text `{site} site on server2`. httpd must start at boot and SELinux must stay enforcing: label the folder with a permanent file context rule, and label the port for the web server.
@check server2 | httpd is enabled and active
systemctl is-enabled httpd && systemctl is-active httpd
@check server2 | the page is served on port {port}, and nothing listens on port 80
curl -s -m 5 http://localhost:{port}/ | grep -q '{site} site on server2' && ! ss -tln | grep -q ':80 '
@check server2 | SELinux is enforcing, port {port} is http_port_t
test "$(getenforce)" = Enforcing && semanage port -l | grep '^http_port_t' | grep -qw {port}
@check server2 | a permanent fcontext rule covers /srv/{site} and the page is labelled httpd_sys_content_t
semanage fcontext -l -C | grep '^/srv/{site}' | grep -q httpd_sys_content_t && ls -Z /srv/{site}/html/index.html | grep -q httpd_sys_content_t
@solution server2
dnf -y install httpd
mkdir -p /srv/{site}/html
echo '{site} site on server2' > /srv/{site}/html/index.html
semanage fcontext -a -t httpd_sys_content_t '/srv/{site}(/.*)?'
restorecon -Rv /srv/{site}
sed -i 's/^Listen 80$/Listen {port}/' /etc/httpd/conf/httpd.conf
printf '<VirtualHost *:{port}>\n    DocumentRoot /srv/{site}/html\n    <Directory /srv/{site}/html>\n        Require all granted\n    </Directory>\n</VirtualHost>\n' > /etc/httpd/conf.d/{site}.conf
semanage port -a -t http_port_t -p tcp {port}
systemctl enable --now httpd
curl http://localhost:{port}/
@explain
Three pieces have to agree. The Listen line decides the port; SELinux lets httpd bind only ports of the type http_port_t, and {port} is not one of them until semanage port -a adds it (without it httpd fails to start and ausearch -m AVC shows a name_bind denial). Files under /srv get the type var_t, which httpd may not read: semanage fcontext -a writes a permanent rule, and restorecon applies it to the files that exist. The mounted xfs volume is labelled the same way, so run restorecon after the mount. chcon would work only until the next relabel.
@endtask

@task t06 | Networking | 10 | server2
Only server1 (192.168.50.11) may reach the web site on server2's port {port}; do not open the port or the http service for everybody. On server1, the name `{webname}` must resolve to 192.168.50.12 (use /etc/hosts), and `curl http://{webname}:{port}/` on server1 must show the page.
@check server1 | {webname} resolves to 192.168.50.12 on server1
getent hosts {webname} | grep -q '^192\.168\.50\.12[[:space:]]'
@check server1 | server1 gets the page by name
curl -s -m 5 http://{webname}:{port}/ | grep -q '{site} site on server2'
@check server2 | a rule or zone names 192.168.50.11
firewall-cmd --list-all-zones | grep -q '192\.168\.50\.11'
@check server2 | the port is not open to everybody in the public zone
! firewall-cmd --zone=public --list-ports | grep -qw '{port}/tcp' && ! firewall-cmd --zone=public --list-services | grep -qw http
@solution server2
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.50.11/32" port port="{port}" protocol="tcp" accept'
firewall-cmd --reload
firewall-cmd --list-rich-rules
@solution server1
echo '192.168.50.12 {webname}' >> /etc/hosts
curl http://{webname}:{port}/
@explain
A rich rule ties a source address, a port and an action together, so only that one machine gets in. The other way is a zone with a source: firewall-cmd --zone=internal --add-source=192.168.50.11/32 and the port added to that zone; packets from server1 then use the internal zone and everybody else stays in public. Both need --permanent and a --reload. /etc/hosts is read before DNS (the hosts line in /etc/nsswitch.conf says files dns), which is why one line there is enough; getent hosts NAME tests it the same way programs do.
@endtask

@task t07 | Users and groups | 15 | server2
On server2, accounts created from now on must get these password aging values by default: at most {maxdays} days between password changes, at least {mindays} day(s), and a warning {warn} days before the password expires. Then create the group `{grp}` with the GID {gid}, the users `{u1}` and `{u2}` with `{grp}` as a secondary group, and the user `{aud}`, who is not in `{grp}`. All three use the password `{upw}`.
@check server2 | login.defs has the three defaults
grep -Eq '^PASS_MAX_DAYS[[:space:]]+{maxdays}$' /etc/login.defs && grep -Eq '^PASS_MIN_DAYS[[:space:]]+{mindays}$' /etc/login.defs && grep -Eq '^PASS_WARN_AGE[[:space:]]+{warn}$' /etc/login.defs
@check server2 | the three users got those aging values
for u in {u1} {u2} {aud}; do test "$(getent shadow $u | cut -d: -f4-6)" = "{mindays}:{maxdays}:{warn}" || exit 1; done
@check server2 | {grp} has GID {gid}; {u1} and {u2} are members, {aud} is not
test "$(getent group {grp} | cut -d: -f3)" = {gid} && id -nG {u1} | grep -qw {grp} && id -nG {u2} | grep -qw {grp} && ! id -nG {aud} | grep -qw {grp}
@check server2 | the passwords work
certlab-check password {u1} '{upw}' && certlab-check password {u2} '{upw}' && certlab-check password {aud} '{upw}'
@solution server2
sed -i 's/^PASS_MAX_DAYS.*/PASS_MAX_DAYS\t{maxdays}/' /etc/login.defs
sed -i 's/^PASS_MIN_DAYS.*/PASS_MIN_DAYS\t{mindays}/' /etc/login.defs
sed -i 's/^PASS_WARN_AGE.*/PASS_WARN_AGE\t{warn}/' /etc/login.defs
grep ^PASS_ /etc/login.defs
groupadd -g {gid} {grp}
useradd -G {grp} {u1}
useradd -G {grp} {u2}
useradd {aud}
for u in {u1} {u2} {aud}; do echo '{upw}' | passwd --stdin $u; done
chage -l {u1}
@explain
useradd copies PASS_MAX_DAYS, PASS_MIN_DAYS and PASS_WARN_AGE from /etc/login.defs into the new account's line in /etc/shadow (fields 5, 4 and 6). The file is read only when an account is created, so the order of the steps matters: accounts made before the change keep the old values, and chage -M / -m / -W would have to fix them one by one. chage -l shows what an account got.
@endtask

@task t08 | File systems | 15 | server2
Create the project folder /projects/{site} on server2. It belongs to the group `{grp}`; members of `{grp}` can read, write and enter it, and other users have no access (mode 2770, so new files belong to `{grp}`). Every file created in it later must be readable and writable by all members of `{grp}`. The user `{aud}` must be able to read the folder and every file in it, including files created later, but must not be able to change them.
@check server2 | /projects/{site} has group {grp} and mode 2770
test "$(stat -c '%G %a' /projects/{site})" = "{grp} 2770"
@check server2 | {aud} has r-x on the folder and as a default
getfacl -p /projects/{site} 2>/dev/null | grep -q '^user:{aud}:r-x' && getfacl -p /projects/{site} 2>/dev/null | grep -q '^default:user:{aud}:r-x'
@check server2 | a new file of {u1} is writable by {u2} and readable, not writable, by {aud}
f=/projects/{site}/grader-check.txt; rm -f $f; su - {u1} -c "echo first > $f" && su - {u2} -c "echo second >> $f" && su - {aud} -c "cat $f" | grep -q second && ! su - {aud} -c "echo third >> $f" 2>/dev/null
@solution server2
mkdir -p /projects/{site}
chgrp {grp} /projects/{site}
chmod 2770 /projects/{site}
setfacl -m u:{aud}:rx /projects/{site}
setfacl -m d:u:{aud}:rx,d:g:{grp}:rwx /projects/{site}
getfacl /projects/{site}
@explain
Mode 2770 keeps everybody else out and the set-GID bit makes new files belong to {grp}, but it does not decide their permissions: the creator's umask (022) would leave the group read-only. A default ACL (d: entries) on the folder is copied onto every new file and folder made in it, and while one exists the umask is not applied, so the group gets rw. The normal ACL entry u:{aud}:rx lets {aud} into the folder; the default entry d:u:{aud}:rx gives {aud} read access to the files of the future (on files the x is masked away, getfacl shows #effective:r--). setfacl -R -m would also cover files that already exist.
@endtask

@task t09 | Users and groups | 10 | server2
Members of `{grp}` may run exactly two commands as root with sudo, without a password: `systemctl restart httpd` and `systemctl status httpd`. They may not run anything else as root. Put the rule in a file in /etc/sudoers.d.
@check server2 | {u1} can restart and check httpd with sudo
su - {u1} -c 'sudo -n /usr/bin/systemctl restart httpd' && su - {u1} -c 'sudo -n /usr/bin/systemctl status httpd' >/dev/null
@check server2 | {u1} cannot run other commands as root
! su - {u1} -c 'sudo -n /usr/bin/systemctl restart sshd' >/dev/null 2>&1 && ! su - {u1} -c 'sudo -n /usr/bin/cat /etc/shadow' >/dev/null 2>&1
@check server2 | the rule is in /etc/sudoers.d and the files are valid
grep -rqs '%{grp}' /etc/sudoers.d/ && visudo -c >/dev/null
@solution server2
echo '%{grp} ALL=(root) NOPASSWD: /usr/bin/systemctl restart httpd, /usr/bin/systemctl status httpd' > /etc/sudoers.d/{grp}
chmod 440 /etc/sudoers.d/{grp}
visudo -c
su - {u1} -c 'sudo -n -l'
@explain
% in front of a name makes the rule apply to a group. A command written with its arguments allows exactly those arguments, so restart httpd is allowed and restart sshd is not; a command without arguments would allow any arguments. Commands need their full path (which systemctl shows it). Check every change with visudo -c: a broken sudoers file stops sudo for everybody, including you.
@endtask

@task t10 | Security | 15 | server1
The user `{svc}` exists on server2 with the password `{spw}`. Create `{svc}` on server1 too (password `{spw}`) and set it up so that {svc} on server1 can log in to server2 as {svc} with an SSH key, without typing a password.
@check server1 | key login from server1 to server2 works for {svc}
certlab-check sshkey {svc} {svc}@server2
@solution server1
useradd {svc}
echo '{spw}' | passwd --stdin {svc}
su - {svc}
ssh-keygen -t ed25519 -N '' -f ~/.ssh/id_ed25519
ssh-copy-id -o StrictHostKeyChecking=no {svc}@server2
{spw}
ssh {svc}@server2 hostname
exit
@explain
ssh-keygen makes the key pair in ~/.ssh of the user who runs it: the private key stays on server1, and ssh-copy-id appends the public half to ~/.ssh/authorized_keys of {svc} on server2 (the password is needed one last time for that). Do it as {svc}, not as root, or the keys end up in root's folder and {svc} still has to type a password. -N '' gives the key an empty passphrase, which a service account needs to run unattended.
@endtask

@task t11 | Running systems | 10 | server1
As `{svc}`, copy the report /srv/reports/{rep}.txt from server1 to the folder /home/{svc}/incoming on server2 (create the folder). Use a secure transfer over SSH.
@check server2 | the report arrived intact and belongs to {svc}
f=/home/{svc}/incoming/{rep}.txt; test "$(stat -c %U $f 2>/dev/null)" = {svc} && grep -q 'report {rep} for {site}' $f && grep -q 'total 42' $f

@task t12 | Containers | 25 | server1
On server1, run a rootful container named `{cname}` from the image registry.lab.example.com/library/nginx. It must:
- publish container port 80 on host port {cport}, reachable from server2 through the firewall
- keep its web files in a podman volume named `{vol}`, mounted on /usr/share/nginx/html; the volume holds an index.html with the text `{cname} in a container`
- start at boot as the system service `{cname}.service`, defined by a Quadlet file in /etc/containers/systemd
@check server1 | the volume {vol} exists and the container uses it
podman volume ls | grep -qw {vol} && podman inspect {cname} | grep -q 'volumes/{vol}/_data'
@check server1 | a Quadlet file in /etc/containers/systemd defines the container
grep -rqs 'Image=.*nginx' /etc/containers/systemd/
@check server1 | after the reboot the service is active
systemctl is-active {cname}.service
@check server2 | server2 gets the page on port {cport}
curl -s -m 5 http://server1.lab.example.com:{cport}/ | grep -q '{cname} in a container'
@solution server1
dnf -y install container-tools
podman login -u student -p student registry.lab.example.com
podman volume create {vol}
podman volume inspect {vol}
echo '{cname} in a container' > /var/lib/containers/storage/volumes/{vol}/_data/index.html
mkdir -p /etc/containers/systemd
cat > /etc/containers/systemd/{cname}.container <<'EOF'
[Unit]
Description=nginx web container

[Container]
ContainerName={cname}
Image=registry.lab.example.com/library/nginx
PublishPort={cport}:80
Volume={vol}:/usr/share/nginx/html:Z

[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl start {cname}.service
firewall-cmd --permanent --add-port={cport}/tcp
firewall-cmd --reload
curl http://localhost:{cport}/
@explain
A named volume is storage that podman manages: podman volume create makes it, and podman volume inspect shows its Mountpoint on the host, where you can put files. For root, Quadlet reads .container files in /etc/containers/systemd and, at every systemctl daemon-reload, generates a service named after the file. The [Install] section with WantedBy=multi-user.target starts it at boot; a generated unit cannot be enabled with systemctl enable, so that section is the way. The image is pulled once and kept, so the service still starts after a reboot, when the registry login has been forgotten. The firewall opens the host port, not the container port.
@endtask

@task t14 | Shell scripts | 20 | server1
Write the script /usr/local/bin/{script}. It takes exactly one argument, the name of a folder, and makes a gzip-compressed tar archive of it called /backups/NAME-YYYY-MM-DD.tar.gz, where NAME is the last part of the folder's path and YYYY-MM-DD is today's date (create /backups when it is missing). It prints the archive's name. Rules:
- without exactly one argument it prints `Usage: {script} FOLDER` and exits with status 2
- when the argument is not an existing folder it prints `FOLDER is not a folder` (with the name it was given) and exits with status 1, without making an archive
@check server1 | without an argument: the usage line and exit status 2

@check server1 | a missing folder: the message, status 1 and no archive
rm -f /backups/no-such-dir-*; out=$(/usr/local/bin/{script} /tmp/no-such-dir 2>&1); rc=$?; test $rc -eq 1 && echo "$out" | grep -q '/tmp/no-such-dir is not a folder' && ! ls /backups/no-such-dir-* >/dev/null 2>&1
@check server1 | it makes a dated tar.gz of the folder
mkdir -p /tmp/grade-src/sub; echo data > /tmp/grade-src/sub/f.txt; f=/backups/grade-src-$(date +%F).tar.gz; rm -f $f; /usr/local/bin/{script} /tmp/grade-src >/dev/null 2>&1; file $f | grep -q 'gzip compressed' && tar tzf $f | grep -q 'grade-src/sub/f.txt$'
@solution server1
cat > /usr/local/bin/{script} <<'EOF'
#!/bin/bash
if [ $# -ne 1 ]; then
    echo "Usage: {script} FOLDER"
    exit 2
fi
if [ ! -d "$1" ]; then
    echo "$1 is not a folder"
    exit 1
fi
name=$(basename "$1")
archive="/backups/$name-$(date +%F).tar.gz"
mkdir -p /backups
tar czf "$archive" "$1"
echo "$archive"
EOF
chmod +x /usr/local/bin/{script}
{script} /srv/reports
{script} /nowhere
@explain
$# counts the arguments and $1 is the first one; quote it ("$1") so that names with spaces stay whole. [ -d NAME ] is true only for an existing folder, and ! turns the test around. $(...) puts a command's output into the text: basename gives the last part of a path and date +%F prints the date as YYYY-MM-DD. tar c creates, z compresses with gzip, f names the archive. The checks of the bad cases come first and end the script with exit, so nothing is archived by mistake.
@endtask
