@task t01 | Running systems | 15 | server2
Somebody added a line to /etc/fstab on server2 for the ext4 file system on /dev/vdc1, which must be mounted on /backup. The line has a mistake: at the next boot server2 would stop in emergency mode. Fix the line (keep using the UUID) so that /backup is mounted at every boot and server2 boots normally. The files on /backup must stay. Do this task first on server2.
@check server2 | fstab still mounts /backup by UUID
grep -E '^UUID=' /etc/fstab | grep -Eq '[[:space:]]/backup/?[[:space:]]'
@check server2 | server2 boots normally and /backup is the ext4 file system with its files
certlab-check booted && test "$(findmnt -n -o FSTYPE /backup)" = ext4 && grep -q 'keep it' /backup/README.txt
@solution server2
grep backup /etc/fstab
blkid /dev/vdc1
sed -i '/\/backup/s/ xfs / ext4 /' /etc/fstab
grep backup /etc/fstab
systemctl daemon-reload
mount -a
findmnt --verify
reboot
hostname
@explain
blkid shows that /dev/vdc1 holds ext4, but the fstab line says xfs, so the mount fails. A failed mount of a normal fstab line makes local-fs.target fail, and systemd stops in emergency mode. mount -a and findmnt --verify test the file before the reboot does; run systemctl daemon-reload after every change to fstab so systemd reads it again. If a machine is already in emergency mode, give the root password, fix the line, and reboot (or type systemctl default). The option nofail would let the machine boot even when the mount fails, but it hides the problem instead of fixing it.
@endtask

@task t04 | Local storage | 25 | server2
On server2, give /dev/vdb a GPT partition table and create a 2 GiB partition on it. Use the partition for a new volume group `{vg}` whose physical extents are {pe} MiB. @solution server2

@task t05 | Deploy and maintain | 10 | server2
Add the kernel argument `{karg}` to the boot entries of every installed kernel on server2, so that it is used from the next boot on. Do not remove any of the existing arguments.
@check server2 | every boot entry has {karg}

@task t13 | Security | 25 | server1
Apache (httpd) is installed on server1 and configured to serve /var/www/html on port {port}, but it does not start, and the page /var/www/html/index.html (`Welcome to the {team} site`) is not shown. Find the problems and fix them, keeping SELinux enforcing and keeping port {port}. httpd must start at boot.
@check server1 | httpd is enabled and active, still on port {port}
systemctl is-enabled httpd && systemctl is-active httpd && grep -Eq '^Listen +{port}$' /etc/httpd/conf/httpd.conf
@check server1 | the page is served on port {port}
curl -s -m 5 http://localhost:{port}/ | grep -q 'Welcome to the {team} site'
@check server1 | SELinux is enforcing, port {port} is labelled http_port_t
test "$(getenforce)" = Enforcing && semanage port -l | grep '^http_port_t' | grep -qw {port}
@check server1 | the page has the type httpd_sys_content_t
ls -Z /var/www/html/index.html | grep -q httpd_sys_content_t
@solution server1
systemctl start httpd
journalctl -u httpd --no-pager | tail -5
ausearch -m AVC -ts recent
semanage port -a -t http_port_t -p tcp {port}
systemctl enable --now httpd
curl http://localhost:{port}/
ls -Z /var/www/html/index.html
restorecon -v /var/www/html/index.html
curl http://localhost:{port}/
@explain
There are two SELinux problems. First, httpd may only bind ports labelled http_port_t; {port} is not one of them, so httpd fails to start and audit.log has an AVC denial for name_bind. semanage port -a adds the label for good. Second, index.html was created in /root and moved with mv, which keeps the label admin_home_t; httpd may not read that, so the page answers 403 Forbidden. restorecon sets the label the policy expects for that place (httpd_sys_content_t). A file copied with cp gets the label of the folder it lands in, which is why mv is the trap. ausearch -m AVC (or sealert, from setroubleshoot-server) shows what was denied. setenforce 0 would hide both problems, which the task forbids.
@endtask

@task t17 | Essential tools | 10 | server1
In /opt/app/conf there are two configuration files. Make /opt/app/current.conf a symbolic link to the newer one, /opt/app/conf/app-{ver}.conf. Also make /root/app-saved.conf a hard link to that same file, so that its contents stay reachable even if the name in /opt/app/conf is removed.
@check server1 | current.conf is a symbolic link to app-{ver}.conf

@check server1 | app-saved.conf is a hard link to the same file

@solution server1

ln -s /opt/app/conf/app-{ver}.conf /opt/app/current.conf
ln /opt/app/conf/app-{ver}.conf /root/app-saved.conf

@task t18 | Shell scripts | 20 | server1
Write the script /usr/local/bin/{script}. It takes one argument, a number MINUID. For every account in the output of `getent passwd` whose UID is MINUID or higher, it prints one line `NAME UID` (the login name, a space, the UID), in the order getent lists them. Run without an argument, with more than one, or with an argument that is not a whole number, it prints `Usage: {script} MINUID` and exits with status 1.
@check server1 | without an argument or with a word: the usage line and status 1
out=$(/usr/local/bin/{script} 2>&1); rc=$?; test $rc -eq 1 && echo "$out" | grep -q "Usage: {script} MINUID" || exit 1; out=$(/usr/local/bin/{script} abc 2>&1); rc=$?; test $rc -eq 1 && echo "$out" | grep -q "Usage: {script} MINUID"
@check server1 | it lists the accounts from UID 1000 up
test "$(/usr/local/bin/{script} 1000)" = "$(getent passwd | awk -F: '$3 >= 1000 {print $1, $3}')"
@check server1 | another limit gives the right list
test "$(/usr/local/bin/{script} 65000)" = "nobody 65534" && test "$(/usr/local/bin/{script} 0 | head -1)" = "root 0"
@solution server1
cat > /usr/local/bin/{script} <<'EOF'
#!/bin/bash
if [ $# -ne 1 ] || ! [[ $1 =~ ^[0-9]+$ ]]; then
    echo "Usage: {script} MINUID"
    exit 1
fi
getent passwd | while IFS=: read -r name pw uid rest; do
    if [ "$uid" -ge "$1" ]; then
        echo "$name $uid"
    fi
done
EOF
chmod +x /usr/local/bin/{script}
{script} 1000
@explain
A pipe into while read processes another command's output line by line. IFS=: makes read split each line at the colons of /etc/passwd's format, so the third field lands in uid; the last variable (rest) takes whatever is left. [[ $1 =~ ^[0-9]+$ ]] is true when the argument is made of digits only, and -ge compares numbers (>= inside [ ] would compare text). $# is the number of arguments.
@endtask
