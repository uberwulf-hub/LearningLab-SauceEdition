# Unit: u05 | 5. Local storage | Configure local storage

Disks arrive empty. Before you can keep anything on them you split them into partitions, often pool them with LVM (the Logical Volume Manager) so that space can grow later, and tell the system what to mount or use as swap at every boot. This unit covers all of that: looking at disks, partition tables of both kinds (MBR and GPT), physical volumes, volume groups and logical volumes, swap, and /etc/fstab. The golden rule of the whole unit: add new storage without harming what is already there.

## Lesson: l0501 | Disks, partitions and how to look at them

Linux shows every disk as a file in /dev. The name tells you how the disk is connected:

- `/dev/vda`, `/dev/vdb`... are virtual disks in a virtual machine (virtio). The lab machines use these.
- `/dev/sda`, `/dev/sdb`... are SATA, SAS and USB disks.
- `/dev/nvme0n1`, `/dev/nvme1n1`... are NVMe disks. Their partitions get a `p`: `/dev/nvme0n1p1`.
- `/dev/sr0` is a CD or DVD drive.

A partition is numbered after the disk name: `/dev/vdb1` is the first partition on vdb. A disk can also be used whole, without partitions (LVM allows it), but partitions make it clear to anyone looking at the disk what it is used for.

### lsblk: the map of your storage

`lsblk` lists the block devices: disks, the partitions on them, the logical volumes on those, and where each one is mounted. On its own it draws a tree with lines that show what sits on what; `lsblk -l` prints the same as a flat list (used here).

```terminal
[root@server1 ~]# lsblk -l
NAME      MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
vda         252:0  0   20G  0 disk
vda1        252:1  0    1G  0 part /boot
vda2        252:2  0   19G  0 part
rhel-root   253:0  0   17G  0 lvm  /
rhel-swap   253:1  0    2G  0 lvm  [SWAP]
vdb        252:16  0    5G  0 disk
vdc        252:32  0    5G  0 disk
sr0          11:0  1 10.2G  0 rom
```

Read it from the top: vda has two partitions. vda1 holds /boot. vda2 is used by LVM and carries two logical volumes, root (mounted on /) and swap. vdb and vdc have nothing on them yet: these are the disks you may use. Always run lsblk before you touch a disk, so that you never write a partition table over one that is in use.

Useful options: `lsblk -f` adds the file system type, label and UUID; `lsblk -o NAME,SIZE,TYPE` picks the columns; `-b` prints sizes in bytes and `-n` drops the heading line, which is handy in scripts.

### blkid: what is written on a device

`blkid` reads the signature at the start of a device and prints its type, its UUID (a unique ID created when the file system was made) and its label if it has one. `-s UUID -o value` prints only the UUID, ready to paste into a file.

```terminal
[root@server1 ~]# blkid /dev/vda1
/dev/vda1: UUID="e6f1f620-bff5-4488-9a1b-5a107e135a16" BLOCK_SIZE="512" TYPE="xfs" PARTUUID="7d1c109b-01"
[root@server1 ~]# blkid -s UUID -o value /dev/vda1
e6f1f620-bff5-4488-9a1b-5a107e135a16
```

Do not mix up the UUID (it belongs to the file system and changes when you format again) with the PARTUUID (it belongs to the partition table entry).

### Two kinds of partition table: MBR and GPT

The partition table at the start of the disk records where each partition begins and ends. There are two formats:

- **MBR** (also called msdos or dos) is the old format. It allows 4 primary partitions. For more, one of the four becomes an extended partition, a container that holds logical partitions numbered from 5 up. MBR cannot use more than 2 TiB of a disk.
- **GPT** (GUID Partition Table) is the modern format, used by UEFI machines. It allows 128 partitions by default, all of the same kind, handles huge disks, keeps a backup copy of the table at the end of the disk, and lets each partition have a name.

The tools: `fdisk` works on both kinds, `gdisk` only on GPT, and `parted` on both (and can run without questions, which is perfect for scripts and exams). Next lessons show each one.

```terminal
[root@server1 ~]# fdisk -l /dev/vda
Disk /dev/vda: 20 GiB, 21474836480 bytes, 41943040 sectors
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes
I/O size (minimum/optimal): 512 bytes / 512 bytes
Disklabel type: dos
Disk identifier: 0x7d1c109b

Device    Boot   Start      End  Sectors Size Id Type
/dev/vda1 *       2048  2099199  2097152   1G 83 Linux
/dev/vda2      2099200 41943039 39843840  19G 8e Linux LVM
```

`Disklabel type: dos` means MBR. The `Id` column is the partition type: 83 is a normal Linux partition, 8e is LVM and 82 is swap.

> Sizes: a GiB is 1024 x 1024 x 1024 bytes, a GB is 1000 x 1000 x 1000. Tasks on the exam say MiB and GiB. In parted, write the unit exactly (`1025MiB`, not `1025MB`), or the partition comes out a little smaller than asked.

## Lesson: l0502 | MBR partitions with fdisk

`fdisk DISK` opens an interactive editor for the partition table. Nothing is written until you type `w`, so you can look around and quit with `q` if you change your mind. The commands you need:

- `p` prints the table, `n` adds a partition, `d` deletes one, `t` changes a partition's type
- `o` creates a new empty MBR table, `g` a new empty GPT table (both throw away all partitions)
- `w` writes the changes and quits, `q` quits without writing, `m` shows the help

Pressing Enter at a question takes the default shown in brackets. For the size, `+1G` means "1 GiB from the first sector" and `+512M` means 512 MiB.

Here a new disk gets a 1 GiB Linux partition and a 512 MiB swap partition:

Types that matter on the exam: 83 Linux (the default), 8e Linux LVM, 82 Linux swap. The type is a label for people and tools: LVM and swap work on a partition of type 83 too, but setting the right type is good practice and some tasks ask for it.

### Deleting a partition

Before you delete a partition, make sure nothing uses it: unmount it, swapoff it, remove it from its volume group, and take its line out of /etc/fstab. Then `d` and the partition number:

```terminal
[root@server1 ~]# fdisk /dev/vdb

Welcome to fdisk (util-linux 2.37.4).
Changes will remain in memory only, until you decide to write them.
Be careful before using the write command.

Partition 2 has been deleted.

Command (m for help): w

[root@server1 ~]# lsblk -l /dev/vdb
```

### More than four partitions on MBR

To get a fifth partition on an MBR disk, create partition 4 (or any free number) as `e` (extended) and give it the rest of the disk. After that, `n` offers logical partitions (`l`), numbered 5, 6 and so on, inside the extended one. On a new disk, GPT avoids this complication.

> If the kernel still shows the old layout after you wrote the table (this happens when a partition on the same disk is in use), run `partprobe /dev/vdb` to make it read the table again, then check with lsblk.

## Lesson: l0503 | GPT partitions with gdisk and parted

### gdisk

`gdisk` looks and feels like fdisk but only makes GPT tables. Its partition types are four-digit codes: 8300 Linux file system (the default), 8e00 Linux LVM, 8200 Linux swap, ef00 EFI system. At the end, `w` asks you to confirm.

```terminal
[root@server1 ~]# gdisk /dev/vdc

  APM: not present
  GPT: not present
```

Other gdisk commands: `p` print, `d` delete, `t` change the type, `o` a new empty table, `q` quit without saving.

### parted: partitions without questions

`parted` can do everything in one command line. With `-s` (script mode) it never asks anything, so you can type exactly what you planned. The commands:

- `parted -s DISK mklabel gpt` (or `msdos`) writes a new, empty partition table. This throws away every partition on the disk: only use it on a new disk.
- `parted -s DISK mkpart NAME START END` adds a GPT partition with a name. On an msdos disk the first word is the kind instead: `primary`, `extended` or `logical`. You may add a file system type word before START (`xfs`, `linux-swap`): parted uses it only to set the partition type, it does not format anything.
- `parted -s DISK set NUMBER lvm on` marks a partition for LVM (`swap on` for swap).
- `parted -s DISK rm NUMBER` deletes a partition.
- `parted -s DISK unit MiB print` shows the table in MiB, which makes it easy to see where the free space starts.

```terminal
[root@server2 ~]# parted -s /dev/vdb mklabel gpt
[root@server2 ~]# parted -s /dev/vdb mkpart data xfs 1MiB 1025MiB
Information: You may need to update /etc/fstab.

[root@server2 ~]# parted -s /dev/vdb mkpart lvmpart 1025MiB 3073MiB
Information: You may need to update /etc/fstab.

[root@server2 ~]# parted -s /dev/vdb set 2 lvm on
Information: You may need to update /etc/fstab.

[root@server2 ~]# parted -s /dev/vdb unit MiB print
Model: Virtio Block Device (virtblk)
Disk /dev/vdb: 5120MiB
Sector size (logical/physical): 512B/512B
Partition Table: gpt
Disk Flags:

Number  Start    End      Size     File system  Name     Flags
 1      1MiB     1025MiB  1024MiB               data
 2      1025MiB  3073MiB  2048MiB               lvmpart  lvm

[root@server2 ~]# parted -s /dev/vdb rm 1
Information: You may need to update /etc/fstab.

[root@server2 ~]# parted -s /dev/vdb unit MiB print
Model: Virtio Block Device (virtblk)
Disk /dev/vdb: 5120MiB
Sector size (logical/physical): 512B/512B
Partition Table: gpt
Disk Flags:

Number  Start    End      Size     File system  Name     Flags
 2      1025MiB  3073MiB  2048MiB               lvmpart  lvm
```

Notice three things. START and END are positions on the disk, not sizes: a 1 GiB partition from 1 MiB ends at 1025 MiB. The next partition starts where the previous one ended. And deleting partition 1 did not renumber partition 2: numbers stay with their partitions.

> Plan the sizes on paper first: start at 1MiB, add each size, and write the end of one partition as the start of the next. Always write the unit (MiB or GiB) on both numbers.

## Lesson: l0504 | LVM: physical volumes, volume groups and logical volumes

A partition has a fixed size and lives on one disk. LVM adds a layer that removes both limits:

- A **physical volume** (PV) is a partition or a whole disk prepared for LVM with `pvcreate`.
- A **volume group** (VG) pools one or more PVs into one big store of space (`vgcreate`). The space is cut into equal pieces called physical extents (PE), 4 MiB each by default.
- A **logical volume** (LV) is a slice of a VG that you use like a partition: format it, mount it, use it for swap (`lvcreate`). It can grow later, even across several disks.

The LV appears as /dev/VGNAME/LVNAME (a link to /dev/dm-N) and as /dev/mapper/VGNAME-LVNAME. Both names are stable and safe to use in /etc/fstab.

### Create a PV and a VG

```terminal
[root@server1 ~]# parted -s /dev/vdb mklabel gpt
[root@server1 ~]# parted -s /dev/vdb mkpart lvm1 1MiB 2049MiB
Information: You may need to update /etc/fstab.

[root@server1 ~]# parted -s /dev/vdb set 1 lvm on
Information: You may need to update /etc/fstab.

[root@server1 ~]# pvcreate /dev/vdb1
  Physical volume "/dev/vdb1" successfully created.
[root@server1 ~]# pvs
  PV        VG   Fmt  Attr   PSize PFree
  /dev/vda2 rhel lvm2 a--  <19.00g    0
  /dev/vdb1      lvm2 ---    2.00g 2.00g
[root@server1 ~]# vgcreate -s 8M vgdata /dev/vdb1
  Volume group "vgdata" successfully created
[root@server1 ~]# vgdisplay vgdata
  --- Volume group ---
  VG Name               vgdata
  System ID
  Format                lvm2
  Metadata Areas        1
  Metadata Sequence No  1
  VG Access             read/write
  VG Status             resizable
  MAX LV                0
  Cur LV                0
  Open LV               0
  Max PV                0
  Cur PV                1
  Act PV                1
  VG Size               1.99 GiB
  PE Size               8.00 MiB
  Total PE              255
  Alloc PE / Size       0 / 0
  Free  PE / Size       255 / 1.99 GiB
  VG UUID               TVRgcC-Ax3B-iqbK-Q2Pt-GLJE-M6c2-DsLhrG

```

`vgcreate -s 8M` sets the extent size to 8 MiB. You can only choose it when you create the VG, so read the task carefully. The VG is a little smaller than the partition: LVM keeps some space at the start for its own records (the metadata). If you skip pvcreate, vgcreate runs it for you.

### Create logical volumes: -L or -l

- `lvcreate -n NAME -L SIZE VG` asks for a size (`-L 300M`, `-L 2G`).
- `lvcreate -n NAME -l COUNT VG` asks for a number of extents (`-l 20`). `-l` also understands percentages: `-l 50%FREE` (half of what is free), `-l 100%FREE` (everything left).

An LV is always a whole number of extents. If the size you ask for is not a multiple of the extent size, LVM rounds up and tells you:

```terminal
[root@server1 ~]# lvcreate -n lvone -L 300M vgdata
  Rounding up size to full physical extent 304.00 MiB.
  Logical volume "lvone" created.
[root@server1 ~]# lvcreate -n lvtwo -l 20 vgdata
  Logical volume "lvtwo" created.
[root@server1 ~]# lvs
  LV    VG     Attr         LSize Pool Origin Data% Meta% Move Log Cpy%Sync Convert
  root  rhel   -wi-ao---- <17.00g
  swap  rhel   -wi-ao----   2.00g
  lvone vgdata -wi-a----- 304.00m
  lvtwo vgdata -wi-a----- 160.00m
[root@server1 ~]# ls -l /dev/vgdata
total 0
lrwxrwxrwx. 1 root root 7 Mar  2 04:00 lvone -> ../dm-2
lrwxrwxrwx. 1 root root 7 Mar  2 04:00 lvtwo -> ../dm-3
```

300 MiB is not a multiple of 8 MiB, so lvone got 38 extents (304 MiB). lvtwo is 20 extents of 8 MiB = 160 MiB. When a task gives a number of extents, use -l; when it gives a size, use -L and check that the size fits the extent size.

### The three report commands

- `pvs`, `vgs`, `lvs`: one line per object, the quick overview.
- `pvdisplay`, `vgdisplay`, `lvdisplay`: the long form, including the extent size and the number of extents.
- All three short forms take `-o` to choose columns and `--noheadings` to drop the heading, for example `vgs --noheadings -o vg_extent_size vgdata` or `lvs --units m -o lv_name,lv_size vgdata`.

> The `<` in `<19.00g` means "a little less than": the exact size does not round to the two decimals shown.

@try machines=1
@task t1 | Local storage | 15 | server1

@check server1 | vgdemo uses 8 MiB extents
test "$(vgs --noheadings -o vg_extent_size vgdemo | tr -d ' ')" = "8.00m"
@check server1 | lvdemo is 25 extents (200 MiB)

? Which lvcreate option takes a number of extents instead of a size?

## Lesson: l0505 | Growing a volume group, and taking LVM apart

### More space for a VG: vgextend

When a VG is full, give it another PV. The new space is available at once to every LV in the group; nothing that exists is touched.

```terminal
[root@server1 ~]# parted -s /dev/vdc mklabel gpt
[root@server1 ~]# parted -s /dev/vdc mkpart lvm2 1MiB 1025MiB
Information: You may need to update /etc/fstab.

[root@server1 ~]# parted -s /dev/vdc set 1 lvm on
Information: You may need to update /etc/fstab.

[root@server1 ~]# vgextend vgdata /dev/vdc1
  Physical volume "/dev/vdc1" successfully created.
  Volume group "vgdata" successfully extended
[root@server1 ~]# pvs
  PV        VG     Fmt  Attr    PSize    PFree
  /dev/vda2 rhel   lvm2 a--   <19.00g       0
  /dev/vdb1 vgdata lvm2 a--     1.99g   <1.54g
  /dev/vdc1 vgdata lvm2 a--  1016.00m 1016.00m
[root@server1 ~]# vgs vgdata
  VG     #PV #LV #SN Attr   VSize VFree
  vgdata   2   2   0 wz--n- 2.98g 2.53g
```

vgextend made the new partition a PV by itself (you may run pvcreate first, it does not hurt). Now the VG has two PVs. The opposite is `vgreduce VG PV`, which takes an empty PV out of a group; LVM refuses while an LV still has extents on that PV.

### Taking LVM apart: always from the top down

The layers have to be removed in the reverse order of creation: first what uses the LV, then the LV, then the VG, then the PV label.

1. Stop using the LV: `umount` it (or `swapoff` it), and remove or comment out its line in /etc/fstab. If you forget the fstab line, the next boot stops in emergency mode.
2. `lvremove VG/LV` removes the logical volume and its data (it asks first; `-y` answers yes).
3. `vgremove VG` removes the volume group once it is empty (or removes its remaining LVs after asking).
4. `pvremove PV` wipes the LVM label, so the partition is an ordinary partition again.

```terminal
[root@server1 ~]# lvremove vgdata/lvtwo
Do you really want to remove active logical volume vgdata/lvtwo? [y/n]: y
  Logical volume "lvtwo" successfully removed.
[root@server1 ~]# lvremove -y vgdata/lvone
  Logical volume "lvone" successfully removed.
[root@server1 ~]# vgremove vgdata
  Volume group "vgdata" successfully removed
[root@server1 ~]# pvremove /dev/vdb1 /dev/vdc1
  Labels on physical volume "/dev/vdb1" successfully wiped.
  Labels on physical volume "/dev/vdc1" successfully wiped.
[root@server1 ~]# pvs
  PV        VG   Fmt  Attr   PSize PFree
  /dev/vda2 rhel lvm2 a--  <19.00g    0
```

> Removing is final: there is no undo for lvremove. Read the name twice, and check with lsblk and findmnt that you are about to remove the right thing. Never remove the VG `rhel`: it holds the system itself.

Renaming is easier than removing and recreating: `lvrename VG OLD NEW` and `vgrename OLD NEW` (remember to update /etc/fstab if it uses the /dev/VG/LV name).

@try machines=1
@task t1 | Local storage | 10 | server1

@setup server1

## Lesson: l0506 | Mounting at boot, swap, and adding storage safely

### /etc/fstab

Everything mounted by hand is gone after a reboot. /etc/fstab lists what to mount at boot, one line per file system, with six fields:

1. what to mount: a device name, `UUID=...` or `LABEL=...`
2. where: the mount point (an existing, empty folder), or `none` for swap
3. the file system type: xfs, ext4, vfat, swap, nfs...
4. options: `defaults` is fine for most; separate several with commas (`defaults,noatime`)
5. dump: 0 (not used any more)
6. fsck order: 0 for xfs, swap and NFS (xfs checks itself, which is why RHEL's own xfs lines end in 0 0), 1 for an ext4 root file system, 2 for other ext4 file systems

```terminal
[root@server1 ~]# cat /etc/fstab

#
# /etc/fstab
# Created by anaconda on Mon Mar  2 08:41:17 2026
#
# Accessible filesystems, by reference, are maintained under '/dev/disk/'.
# See man pages fstab(5), findfs(8), mount(8) and/or blkid(8) for more info.
#
# After editing this file, run 'systemctl daemon-reload' to update systemd
# units generated from this file.
#
/dev/mapper/rhel-root   /                       xfs     defaults        0 0
UUID=e6f1f620-bff5-4488-9a1b-5a107e135a16 /boot                   xfs     defaults        0 0
/dev/mapper/rhel-swap   none                    swap    defaults        0 0
```

### Why UUID or LABEL?

Partition names such as /dev/vdb1 depend on the order in which the kernel finds the disks. Add or remove a disk and yesterday's vdc can become today's vdb. A UUID or a label belongs to the file system itself, so it follows the data wherever the disk turns up. (LVM names like /dev/vgdata/lvone are stable too, because LVM finds its PVs by their own labels.)

```terminal
[root@server1 ~]# mkfs.xfs -L DATA /dev/vdb1
meta-data=/dev/vdb1              isize=512    agcount=4, agsize=65536 blks
         =                       sectsz=512   attr=2, projid32bit=1
         =                       crc=1        finobt=1, sparse=1, rmapbt=0
         =                       reflink=1    bigtime=1 inobtcount=1 nrext64=0
data     =                       bsize=4096   blocks=262144, imaxpct=25
         =                       sunit=0      swidth=0 blks
naming   =version 2              bsize=4096   ascii-ci=0, ftype=1
log      =internal log           bsize=4096   blocks=4096, version=2
         =                       sectsz=512   sunit=0 blks, lazy-count=1
realtime =none                   extsz=4096   blocks=0, rtextents=0
Discarding blocks...Done.
[root@server1 ~]# blkid /dev/vdb1
/dev/vdb1: LABEL="DATA" UUID="cf0f7592-ec35-4567-be44-0ea001decb7a" BLOCK_SIZE="512" TYPE="xfs" PARTLABEL="data" PARTUUID="1fbd07df-7247-4727-8f38-b652255b6115"
[root@server1 ~]# mkdir /data
[root@server1 ~]# echo 'LABEL=DATA /data xfs defaults 0 0' >> /etc/fstab
[root@server1 ~]# systemctl daemon-reload
[root@server1 ~]# mount -a
[root@server1 ~]# findmnt /data
TARGET SOURCE    FSTYPE OPTIONS
/data  /dev/vdb1 xfs    rw,relatime,seclabel,attr2,inode64,logbufs=8,logbsize=32k,noquota
```

(Unit 6 covers mkfs and labels in detail.) To put a UUID in fstab without typing it, let the shell fill it in: `echo "UUID=$(blkid -s UUID -o value /dev/vdb1) /data xfs defaults 0 0" >> /etc/fstab`. Use double quotes so that `$(...)` runs, and two `>` so that you add a line instead of replacing the whole file.

> Test every fstab change before you reboot: `mount -a` mounts everything in fstab that is not mounted yet and complains about mistakes. `systemctl daemon-reload` makes systemd read the new fstab (it turns each line into a mount unit). A bad line that you do not test can stop the next boot in emergency mode (unit 6 shows how to recover).

### Swap

Swap is disk space the kernel uses when memory runs short. It can be a partition or an LV. Three steps make a swap area:

1. `mkswap DEVICE` writes the swap signature (and prints its UUID). `mkswap -L NAME` adds a label.
2. A line in /etc/fstab with the mount point `none` and the type `swap`.
3. `swapon -a` activates everything fstab lists as swap (or `swapon DEVICE` for one). `swapon --show` and `free -m` show what is active.

A swap partition (here vdb2, made with type linux-swap and then `mkswap /dev/vdb2`) and a swap LV (made with `lvcreate -n lvswap -L 256M vgsys` and `mkswap /dev/vgsys/lvswap`):

```terminal
[root@server1 ~]# echo "UUID=$(blkid -s UUID -o value /dev/vdb2) none swap defaults 0 0" >> /etc/fstab
[root@server1 ~]# echo '/dev/vgsys/lvswap none swap defaults 0 0' >> /etc/fstab
[root@server1 ~]# swapon -a
[root@server1 ~]# swapon --show
NAME      TYPE      SIZE USED PRIO
/dev/dm-1 partition   2G   0B   -2
/dev/vdb2 partition 512M   0B   -3
/dev/dm-2 partition 256M   0B   -4
[root@server1 ~]# tail -3 /etc/fstab
LABEL=DATA /data xfs defaults 0 0
UUID=bb2390be-cbf1-4977-aa47-64f4787fe594 none swap defaults 0 0
/dev/vgsys/lvswap none swap defaults 0 0
```

The LVs show up as /dev/dm-N in swapon's list (dm-1 is rhel-swap, dm-2 is the new LV). `swapoff DEVICE` turns one off again, which you must do before you remove it.

### Adding storage without harming what is there

Exam tasks often say "the existing swap must stay" or "do not touch the data". In practice:

- Run `lsblk` first. Create new partitions only in free space (`parted -s DISK unit MiB print` shows where the last partition ends), and never run mklabel (or fdisk's o / g) on a disk that has partitions you must keep.
- Add new fstab lines with `>>`, never `>`, which would replace the whole file.
- Add swap; do not replace it: the old swap line stays in fstab, and `swapon --show` should list both.
- Grow a VG with vgextend rather than building a new one, and grow LVs instead of recreating them (unit 6).

@try machines=1
