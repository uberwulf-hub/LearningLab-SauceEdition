@firewall p01 | Security operations | 6
A family clinic runs a patient portal that patients use from home, a records database behind it, a staff network and a guest Wi-Fi network for the waiting room. Administrators manage the database only from one jump host on the staff network. Write the rules for the clinic's firewall, which sits between all of these networks and the internet. Rules are read top to bottom; the first rule that matches decides; anything no rule matches is denied.
rows 6
addr Internal networks = 10.20.0.0/16
addr Staff LAN = 10.20.1.0/24
addr Jump host = 10.20.1.10/32
addr Guest Wi-Fi = 10.20.9.0/24
addr Patient portal = 10.20.2.10/32
addr Records DB = 10.20.3.5/32
ports 22, 53, 80, 443, 1433, 3389
test allow | 198.51.100.23 -> 10.20.2.10 | 443/TCP | patients on the internet reach the patient portal over HTTPS
test allow | 10.20.2.10 -> 10.20.3.5 | 1433/TCP | the patient portal can query the records database
test allow | 10.20.1.10 -> 10.20.3.5 | 22/TCP | the jump host can manage the records database over SSH
test allow | 10.20.1.25 -> 198.51.100.80 | 443/TCP | staff PCs can browse websites on the internet over HTTPS
test allow | 10.20.9.44 -> 198.51.100.80 | 443/TCP | guest devices can browse websites on the internet over HTTPS
test deny | 10.20.9.44 -> 10.20.1.25 | 443/TCP | guest devices cannot reach anything on the clinic's internal networks
test deny | 10.20.9.44 -> 10.20.2.10 | 443/TCP | guest devices cannot reach the portal's internal address either (patients use it from the internet)
test deny | 10.20.1.25 -> 10.20.3.5 | 1433/TCP | staff PCs cannot connect straight to the records database
rule DENY | Guest Wi-Fi | Internal networks | Any | Any
rule ALLOW | Any | Patient portal | 443 | TCP
rule ALLOW | Patient portal | Records DB | 1433 | TCP
rule ALLOW | Jump host | Records DB | 22 | TCP
rule ALLOW | Staff LAN | Any | 443 | TCP
rule ALLOW | Guest Wi-Fi | Any | 443 | TCP
! The guest deny must come first. "Any" as a destination includes the clinic's own 10.20.x.x addresses, so the rule that lets guests browse over 443 would also let them reach staff PCs and the portal if it came before the deny; and the portal rule allows Any source, which includes guests. With DENY Guest Wi-Fi to Internal networks on top, guests can still reach outside websites, because those addresses are not inside 10.20.0.0/16. ALLOW Any to the portal on 443/TCP lets patients in. Only the portal may reach the database on 1433/TCP (SQL Server), so staff PCs fall through to the implicit deny, and SSH to the database is allowed only from the jump host. Staff browsing is ALLOW Staff LAN to Any on 443/TCP. Remote Desktop (3389) and everything else stay blocked by the implicit deny.

@match p04 | Security program management and oversight | 6
A company works with many partners and vendors. Match each situation to the agreement that BEST fits it.
columns Situation | Agreement
= Two universities write down their shared intent to work together on a research project, with no binding terms or payment -> Memorandum of understanding (MOU)
= A hosting provider promises 99.95% uptime each month and service credits if it misses that -> Service level agreement (SLA)
= A design consultant must keep the company's unreleased product plans secret -> Non-disclosure agreement (NDA)
= Two companies set out how they will run a joint venture, share its profits and connect their networks -> Business partners agreement (BPA)
= General terms (payment, liability, confidentiality) that will apply to every future project with an IT supplier -> Master service agreement (MSA)
= The tasks, deliverables and deadline for one website redesign done under those general terms -> Statement of work (SOW)
x Rules of engagement
x Right-to-audit clause
! An MOU records an intention to cooperate and is usually not legally binding. An SLA sets measurable service levels (uptime, response times) and what happens when they are missed. An NDA keeps shared information confidential. A BPA governs a business partnership: who does what, how profits are split, and often how the partners' systems connect. An MSA holds the general terms for a long relationship, and each piece of work under it gets its own SOW (or work order). Rules of engagement set the limits of a penetration test, and a right-to-audit clause is one clause inside a contract, not an agreement type for any of these situations.

@place p05 | Security architecture | 6
A food factory is splitting its network into zones. The production line is run by an industrial control system that must be kept apart from office systems, and visitors get their own Wi-Fi. Place each device or group of devices in the zone where it belongs.
zone internet | Internet
zone dmz | Screened subnet | Edge firewall
zone guest | Visitor network | Edge firewall
zone corp | Office network | Internal firewall
zone ot | Production (ICS) network | Industrial firewall
device VPN concentrator that remote staff connect to -> dmz
device Public DNS server that answers for the factory's domain -> dmz
device Visitors' phones and laptops -> guest
device File server with HR and finance documents -> corp
device Programmable logic controller (PLC) on the packing line -> ot
device Operator workstation (HMI) that controls the line -> ot
device Passive sensor that learns normal ICS traffic and alerts on changes -> ot
! The VPN concentrator and the public DNS server must accept connections from the internet, so they sit in the screened subnet, where a compromise does not reach the inside directly. Visitors' devices are untrusted and go on their own network that reaches only the internet. The HR and finance file server belongs on the office network behind the internal firewall. The PLC and the HMI run the production line, so they belong in the separate ICS zone behind its own firewall, away from office PCs and email. The passive sensor must see the ICS traffic to learn what is normal there, so it is placed in the production network (on a tap or mirror port, so it cannot disturb the controllers).

@choice q004 | General security concepts | 1
A web server's private key was stolen. The team fears the attacker also recorded months of encrypted traffic to that server. The server used only ECDHE key exchange. Why can't the attacker decrypt those recordings with the stolen key?
- ECDHE uses a 512-bit hash that cannot be reversed
- The server's certificate was extended validation (EV)
+ Each session key came from temporary key pairs that were thrown away, so the long-term key never protected them (perfect forward secrecy)
- TLS compresses traffic, so recordings are useless
! With ephemeral Diffie-Hellman (ECDHE), each session's key is agreed with throwaway key pairs; the server's long-term key only signs the exchange. Stealing that key later does not reveal past session keys. This property is perfect forward secrecy.
