@firewall p01 | Security operations | 6
A small company has a staff network and a screened subnet with a web server and a mail gateway. One staff PC is infected and must be cut off until it is cleaned. Write the rules for the firewall between these networks and the internet. Rules are read top to bottom; the first rule that matches decides; anything no rule matches is denied.
rows 6
addr Internet = 0.0.0.0/0
addr Staff LAN = 10.10.1.0/24
addr Admin PC = 10.10.1.50/32
addr Quarantined PC = 10.10.1.66/32
addr Web server = 10.10.2.20/32
addr Mail gateway = 10.10.2.25/32
ports 22, 25, 53, 80, 443, 3389
test allow | 203.0.113.40 -> 10.10.2.20 | 443/TCP | customers on the internet reach the web server over HTTPS
test allow | 10.10.1.77 -> 10.10.2.20 | 443/TCP | staff on the LAN reach the web server over HTTPS
test allow | 198.51.100.7 -> 10.10.2.25 | 25/TCP | outside mail servers can deliver email to the mail gateway
test allow | 10.10.1.50 -> 10.10.2.20 | 22/TCP | the admin PC can manage the web server over SSH
test allow | 10.10.2.25 -> 198.51.100.53 | 53/UDP | the mail gateway can look up names on outside DNS servers
test deny | 10.10.1.77 -> 10.10.2.20 | 22/TCP | other staff PCs cannot open SSH to the web server
test deny | 203.0.113.40 -> 10.10.2.20 | 3389/TCP | nobody on the internet can use Remote Desktop on the servers
test deny | 10.10.1.66 -> 10.10.2.20 | 443/TCP | the quarantined PC reaches nothing at all, not even the web server
rule DENY | Quarantined PC | Any | Any | Any
rule ALLOW | Any | Web server | 443 | TCP
rule ALLOW | Any | Mail gateway | 25 | TCP
rule ALLOW | Admin PC | Web server | 22 | TCP
rule ALLOW | Mail gateway | Any | 53 | UDP
! The quarantine rule (DENY, source Quarantined PC, everything) must be at the top: the HTTPS rule allows Any source, which includes 10.10.1.66, so if the deny came after it the infected PC could still reach the web server. ALLOW Any to the web server on 443/TCP covers both customers and staff. ALLOW Any to the mail gateway on 25/TCP lets outside servers deliver mail (SMTP). SSH is allowed only from the Admin PC, so other staff PCs fall through to the implicit deny. DNS lookups use 53/UDP from the mail gateway to Any. Remote Desktop (3389) is never allowed, so the implicit deny blocks it; no explicit deny row is needed for it.

@match p03 | General security concepts | 6
Match each need to the technique or tool that meets it BEST.
columns Need | Technique or tool
= Prove a software update came from the vendor and was not changed -> Digital signature
= Keep only a stand-in value for each card number, with the real numbers in a separate secure vault -> Tokenization
= Hide a short message inside an ordinary-looking photo -> Steganography
= Keep a laptop's disk encryption key in a chip on the motherboard, released only if the boot was not tampered with -> Trusted Platform Module (TPM)
= Create and guard a certificate authority's private keys in a tamper-resistant appliance in the data center -> Hardware security module (HSM)
= Show call-center staff only the last four digits of a customer's phone number -> Data masking
= Make stored password hashes slow to crack by running the hash function many thousands of times -> Key stretching
x Key escrow
x Symmetric encryption
! A digital signature (a hash signed with the vendor's private key) proves origin and integrity. Tokenization swaps the real value for a token that is useless on its own; the mapping lives in a vault. Steganography hides that a message exists at all. A TPM is a chip in the computer that stores keys and checks the boot (measured boot); an HSM is a separate, often network-attached, appliance built to create and protect high-value keys such as a CA's. Data masking hides part of a value from people who don't need all of it. Key stretching (PBKDF2, bcrypt, Argon2) repeats the work so each guess costs more. Key escrow (a third party holding a copy of a key) and symmetric encryption (one shared key) do not fit any need as well.

@place p04 | Security architecture | 6
A company is redesigning its network into separate zones. Administrators must go through one hardened system before they can reach any device's admin interface. Place each device in the zone where it belongs.
zone internet | Internet
zone dmz | Screened subnet | Edge firewall
zone servers | Internal servers | Internal firewall
zone staff | Staff network | Internal firewall
zone mgmt | Management network | Internal firewall
device Reverse proxy for the public website -> dmz
device Email security gateway that receives outside mail -> dmz
device Database with customer records -> servers
device Domain controller (directory server) -> servers
device Employee desktop PCs -> staff
device Jump server that administrators use to reach servers -> mgmt
device Management interfaces of the switches and firewalls -> mgmt
! The reverse proxy and the email security gateway take connections straight from the internet, so they go in the screened subnet, where a break-in does not reach the inside network directly. The customer database and the domain controller hold the most valuable data and should never be reachable from the internet, so they sit in the internal server zone behind the internal firewall. Employee PCs get their own staff zone, separate from the servers, so one infected PC cannot reach everything. The jump server and the devices' management interfaces belong in the management network: admins connect to the jump server first, and only it can reach the admin interfaces.

@risk p05 | Security program management and oversight | 6
A distribution company keeps its order servers in a basement room. The equipment and the work to rebuild the room are valued at $400,000. A flood would damage about 25% of that value. Based on past records, a flood like this is expected about once every 5 years. A contractor offers raised flooring, water sensors and a pump for $6,000 per year (spread over the life of the equipment), which would cut the expected floods to once every 20 years.
calc sle | Single loss expectancy (SLE), in dollars | = 400000 * 0.25
calc ale | Annualized loss expectancy (ALE) today, in dollars per year | = 400000 * 0.25 * 0.2
calc ale2 | ALE with the contractor's controls, in dollars per year | = 400000 * 0.25 * 0.05
? worth | Is the contractor's offer worth it?
+ Yes: it lowers the ALE by $15,000 a year and costs $6,000 a year, saving about $9,000 a year
- No: it costs more each year than the ALE it removes
- Yes, but only because it brings the ALE to zero
- It can't be judged without the risk owner's name
? strategy | Instead of the contractor, the company could buy flood insurance. Which risk strategy would that be?
- Mitigation
- Acceptance
+ Transference
- Avoidance
! SLE = asset value x exposure factor = $400,000 x 0.25 = $100,000. Once every 5 years is an ARO of 0.2, so ALE = SLE x ARO = $100,000 x 0.2 = $20,000 a year. Once every 20 years is an ARO of 0.05, so the new ALE = $100,000 x 0.05 = $5,000 a year. The control removes $15,000 of expected loss a year and costs $6,000, so it is worth it (net saving $9,000). It does not bring the ALE to zero. The control itself is mitigation; insurance moves the money impact to the insurer, which is transference.

@multi q006 | General security concepts | 1
A developer is building a sign-in system and must store passwords so that a stolen copy of the database is hard to crack. Which TWO measures should she use? (Choose two.)
- Encrypt the passwords with AES and keep the key in the same database
+ Add a unique random salt to each password before hashing it
- Hash each password once with MD5
+ Use a slow password hashing function such as Argon2 or bcrypt
- Store the passwords in Base64 so they are not readable at a glance
! A unique salt makes identical passwords hash differently and makes precomputed rainbow tables useless. A slow, key-stretching function makes every guess expensive. MD5 is fast and broken, Base64 is just encoding, and an encryption key stored next to the data is stolen with it.
