# Exam: exam-3 | Practice exam 3 | 100
The third full practice exam: questions of every kind, a case study about a manufacturer, and five hands-on tasks in the practice portal and on the devices. The tenant is Riverbend Outfitters, as in the course; before you start, its automatic enrolment covers only the group Intune pilot users.

tag = Sales | Field | Retail
@endvars

@setup portal
tenant mdmScope=Some mdmGroup="Intune pilot users"

@task t01 | Enrollment | 4 | RB-LT-003
Sam Ortiz will use the new laptop **RB-LT-003**, which is still in its out-of-box experience and isn't registered for Autopilot. Set it up for Sam with his work account so that it is **Microsoft Entra joined and enrolled in Intune**, without changing who else is enrolled automatically.
@check portal | RB-LT-003 is joined and enrolled, with Sam as its user
device["LB14-55821"].join == "Entra joined"
device["LB14-55821"].managed == Intune
device["LB14-55821"].user == sam
@check portal | the MDM user scope still covers only the pilot group
tenant.mdmScope == Some
@solution portal
members add "Intune pilot users" sam
@solution RB-LT-003
#oobe sam
@explain
With the MDM user scope set to Some, only members of its group are enrolled when they join a device. Adding Sam to Intune pilot users enrols his laptop without enrolling everyone. Setting the scope to All would also work for Sam, but it changes who else is enrolled.
@endtask

@task t02 | Apps | 4 | portal
On iPhones, Sales users may reach Office 365 only from Outlook or Teams protected by an app protection policy. Create an iOS/iPadOS app protection policy **Protect mail {n}** for Microsoft Outlook and Microsoft Teams that requires a PIN and blocks saving copies of company data, assigned to **Sales**, and a Conditional Access policy **Protected apps {n}** (On) for Sales, Office 365, iOS, that requires an app protection policy.
@check portal | the app protection policy
appProtection["Protect mail {n}"].targetApps has "Microsoft Outlook"
appProtection["Protect mail {n}"].pin == Require
appProtection["Protect mail {n}"].saveCopies == Block
appProtection["Protect mail {n}"].include has Sales
@check portal | Outlook gets in, an unprotected app doesn't
signin(user=jordan, device="Jordan's iPhone", client=mobile, clientApp="Microsoft Outlook", mfa=yes) == Allowed
signin(user=jordan, device="Jordan's iPhone", client=mobile, clientApp="Microsoft Word", mfa=yes) == Blocked
@solution portal
create appProtection name="Protect mail {n}" platform=iOS/iPadOS targetApps="Microsoft Outlook,Microsoft Teams" pin=Require saveCopies=Block
assign appProtection "Protect mail {n}" Sales
create ca name="Protected apps {n}" usersInclude=Sales apps="Office 365" platforms=iOS grant="Grant access" controls="Require app protection policy" state=On
@explain
App protection policies are assigned to user groups and work with or without enrolment. The Conditional Access grant "Require app protection policy" lets in only client apps that a policy protects for that user; Word isn't in this policy, so it is refused.
@endtask

@task t03 | Protection | 4 | portal
Encrypt **RB-LT-002** with BitLocker silently (its user is a standard user), with XTS-AES 256-bit and the recovery key backed up to Microsoft Entra ID. Assign the policy to **Pilot devices**. Wait until the encryption has finished and the device has reported it.
@check portal | the policy can encrypt silently
count(diskEncryption, requireEncryption=Enabled, allowWarning=Disabled, standardUser=Enabled) >= 1
@check portal | RB-LT-002 is encrypted and its key is in Microsoft Entra ID
device["RB-LT-002"].bitlocker == On
device["RB-LT-002"].bitlockerMethod == "XTS-AES 256-bit"
device["RB-LT-002"].recoveryKeyIn == "Microsoft Entra ID"
@solution portal
create diskEncryption name="Silent BitLocker {n}" requireEncryption=Enabled allowWarning=Disabled standardUser=Enabled osMethod="XTS-AES 256-bit" backup=Enabled
assign diskEncryption "Silent BitLocker {n}" "Pilot devices"
remote sync RB-LT-002
#wait 7200
remote sync RB-LT-002
@explain
Silent encryption needs Require Device Encryption, Allow Warning For Other Disk Encryption set to Disabled and, for standard users, Allow Standard User Encryption. Encryption takes a while; the next check-in reports it.
@endtask

@task t05 | Configuration | 3 | RB-LT-001
Every Windows device must have the registry value **HKLM\SOFTWARE\Riverbend**, **Team** = **{tag}**, written by a platform script called **Team tag {n}** that runs as SYSTEM. Make sure RB-LT-001 has it.
@check RB-LT-001 | the value is on the device
(Get-ItemProperty -Path HKLM:\SOFTWARE\Riverbend -Name Team).Team -eq '{tag}'
@check portal | it came from the platform script
script["Team tag {n}"].include has "Windows devices"
device["RB-LT-001"].policy["Team tag {n}"] == Succeeded
@solution portal
create script name="Team tag {n}" content="New-Item -Path HKLM:\SOFTWARE\Riverbend -Force | Out-Null; Set-ItemProperty -Path HKLM:\SOFTWARE\Riverbend -Name Team -Value '{tag}'" runAsUser=No
assign script "Team tag {n}" "Windows devices"
remote sync RB-LT-001
@explain
Devices > Scripts and remediations > Platform scripts. Scripts run through the Intune Management Extension, as SYSTEM unless "Run this script using the logged on credentials" is Yes, and once per device (again only if the script changes).
@endtask

@case cs1 | Fernvale Manufacturing
## Overview
Fernvale Manufacturing (a made-up company) makes garden furniture in one factory and has a sales office in another city. 300 staff have Microsoft 365 E3 licences, and Intune manages the Windows devices.

## Existing environment
Office staff use Windows 11 laptops that are Microsoft Entra joined. On the factory floor, shared Windows PCs are used by several people in each shift; everyone signs in with their own account. Engineers use a design app whose installer needs a vendor runtime installed first. The sales team gets company-owned iPads, bought through Apple Business Manager. About 40 contractors work for Fernvale for a few months each, from their own PCs.

## Requirements
- Contractors get a managed Windows desktop they reach from their own PCs; Fernvale doesn't ship them hardware.
- The design app installs on engineers' laptops only after the runtime is in place, without engineers doing anything.
- The sales iPads are supervised and enrolled automatically the first time they are switched on.
- Factory PCs never restart for updates during the day shift (06:00 to 18:00).
- Office 365 can be reached only from devices Intune reports as compliant.
@endcase

@choice c1 | Deployment | 1 | case=cs1
What should Fernvale give the contractors?
- Microsoft Entra registered access from their own PCs
+ Windows 365 Cloud PCs, managed with Intune
- Laptops set up with Windows Autopilot self-deploying mode
- A provisioning package for their own PCs
! A Cloud PC is a Windows desktop in Microsoft's cloud that the contractor opens from any device; Intune manages it like a physical PC, and nothing has to be shipped. Their own PCs stay theirs.

@choice c2 | Apps | 1 | case=cs1
How do you make sure the runtime is installed before the design app?
+ Add both as Win32 apps and make the runtime a dependency of the design app, installed automatically
- Assign the runtime as Available and the design app as Required
- Make the design app supersede the runtime
- Put both installers in one platform script
! A dependency is installed first (with automatic install, even if the runtime isn't assigned itself), and the design app installs only when it succeeded. Supersedence is for replacing an app.

@choice c3 | Enrollment | 1 | case=cs1
Which enrolment method meets the requirement for the sales iPads?
- User enrolment through Company Portal
+ Automated Device Enrollment through Apple Business Manager
- Microsoft Entra registration on each iPad
- A provisioning package
! Automated Device Enrollment (ADE) enrols company-owned Apple devices bought through Apple Business Manager as soon as they are set up, and makes them supervised.

@yesno c4 | Updates | 3 | case=cs1
For the factory PCs, decide whether each statement is true.
Y Active hours from 06:00 to 18:00 in their update ring keep Windows from restarting by itself during the day shift, as long as no update deadline has passed.
N Active hours can cover the whole 24 hours.
Y The factory PCs can have their own ring, assigned to a group of those PCs.
! Windows doesn't restart automatically during active hours, which can be up to 18 hours long; only once an update's deadline (plus grace period) has passed is a restart forced regardless of active hours, so give the factory ring deadlines long enough for a restart outside the shift. A separate ring for a device group lets the factory PCs have their own settings.
