# Exam: exam-2 | Practice exam 2 | 100
A second full practice exam: questions of every kind, a case study about a library service, and four hands-on tasks in the practice portal (one starts on the new laptop RB-LT-003). The tenant is Riverbend Outfitters, as in the course.

@task t01 | Configuration | 4 | portal
Create a settings catalog profile for Windows 10 and later called **No USB writing {n}** that denies write access to removable disks. Assign it to **Corporate Windows devices** and make sure **RB-LT-001** has the setting.
@check portal | the profile sets Removable Disk Deny Write Access
config["No USB writing {n}"].type == "Settings catalog"
config["No USB writing {n}"].setting["Storage/RemovableDiskDenyWriteAccess"] == Enabled
config["No USB writing {n}"].include has "Corporate Windows devices"
@check portal | RB-LT-001 has the setting
device["RB-LT-001"].setting["Storage/RemovableDiskDenyWriteAccess"] == Enabled
@solution portal
create config name="No USB writing {n}" platform="Windows 10 and later" type="Settings catalog" s:Storage/RemovableDiskDenyWriteAccess=Enabled
assign config "No USB writing {n}" "Corporate Windows devices"
remote sync RB-LT-001
@explain
Devices > Configuration > Create > Windows 10 and later > Settings catalog; search for "removable disk" and add Removable Disk Deny Write Access (category Storage). The device writes MDM settings under HKLM\SOFTWARE\Microsoft\PolicyManager\current\device on the PC; it gets them at its next check-in.
@endtask

@task t02 | Updates | 4 | portal
Create two update rings. **Pilot ring {n}**: quality update deferral 0 days, feature update deferral 0 days, assigned to **Pilot devices**. **Broad ring {n}**: quality update deferral {defer} days, feature update deferral 0 days, assigned to **Windows devices** but not to Pilot devices. After a sync, RB-LT-002 must use the pilot ring and RB-LT-001 the broad ring.
@check portal | the pilot ring
ring["Pilot ring {n}"].qualityDeferral == 0
ring["Pilot ring {n}"].include has "Pilot devices"
@check portal | the broad ring excludes the pilot devices
ring["Broad ring {n}"].qualityDeferral == {defer}
ring["Broad ring {n}"].include has "Windows devices"
ring["Broad ring {n}"].exclude has "Pilot devices"
@check portal | each device has one ring
device["RB-LT-002"].ring == "Pilot ring {n}"
device["RB-LT-001"].ring == "Broad ring {n}"
@solution portal
create ring name="Pilot ring {n}" qualityDeferral=0 featureDeferral=0
create ring name="Broad ring {n}" qualityDeferral={defer} featureDeferral=0
assign ring "Pilot ring {n}" "Pilot devices"
assign ring "Broad ring {n}" "Windows devices"
assign ring "Broad ring {n}" "Pilot devices" intent=exclude
remote sync RB-LT-001
remote sync RB-LT-002
@explain
Without the exclusion, RB-LT-002 would get both rings, and two rings on one device conflict. Excluding a device group from a policy assigned to a device group works; mixing user and device groups between include and exclude doesn't.
@endtask

@task t03 | Compliance | 4 | portal
Create a Conditional Access policy called **MFA for everyone {n}**: every user except the emergency access account **breakglass** must use multifactor authentication for all cloud apps. Turn it **On**.
@check portal | the policy is on and covers everyone but breakglass
ca["MFA for everyone {n}"].state == On
ca["MFA for everyone {n}"].usersExclude has breakglass
@check portal | sign-ins ask for MFA, the emergency account doesn't
signin(user=sam, device=RB-DT-010) == "Allowed after MFA"
signin(user=breakglass) == Allowed
@solution portal
create ca name="MFA for everyone {n}" usersInclude="All users" usersExclude=breakglass apps="All cloud apps" grant="Grant access" controls="Require multifactor authentication" state=On
@explain
Conditional Access > Create new policy: Users include All users, exclude the emergency account (so a mistake can't lock everyone out), target all cloud apps, grant access with Require multifactor authentication, and set Enable policy to On (new policies start as Report-only).
@endtask

@case cs1 | Copperfield Library Service
## Overview
Copperfield Library Service (a made-up organisation) runs eight branch libraries. 200 staff have Microsoft 365 E3 licences. All Windows devices are Microsoft Entra joined and enrolled in Intune.

## Existing environment
Each branch has staff laptops and four public PCs for visitors. Staff use their own Android phones for Teams and email. Every branch has a local IT helper who supports that branch's staff. A small IT team at the central office manages Intune.

## Requirements
- IT installs the work apps on the staff's personal Android phones, kept apart from their personal apps and data; IT never sees personal data.
- The public PCs start straight into a set of approved apps (Microsoft Edge and the catalogue app) without anyone signing in.
- Each branch's IT helper can run remote actions on the devices of their own branch only, and sees only that branch's policies.
- Monthly updates first go to ten test laptops; all other devices get them a week later.
- When someone has used a device's local administrator password, it changes soon afterwards.
@endcase

@choice c1 | Enrollment | 1 | case=cs1
How should the staff's personal Android phones be enrolled?
- Android Enterprise fully managed
+ Android Enterprise personally owned with a work profile
- Android Enterprise dedicated devices
- They shouldn't be enrolled at all: app protection policies only
! A work profile keeps work apps and data in their own container on a personal phone; IT manages only that part. Fully managed and dedicated are for company-owned phones. App protection without enrolment protects data in apps, but it can't install the work apps, which the requirement asks for.

- Kiosk mode: Single app, full-screen kiosk
- User logon type: Microsoft Entra user or group

@choice c3 | Monitoring | 1 | case=cs1
How do you give each branch's IT helper what they need, with the least effort?
- Make every helper an Intune Administrator
+ Per branch: a scope tag on that branch's policies, and a Help Desk Operator role assignment with the branch's groups as scope and the branch's tag
- Per branch: a separate Intune tenant
- Per branch: a Conditional Access policy for the helper
! The role assignment's scope groups decide which devices and users the helper can act on; scope tags decide which objects (policies, apps) they see. Intune Administrator would give them everything.

@yesno c4 | Updates | 3 | case=cs1

@choice c5 | Protection | 1 | case=cs1
Which LAPS setting meets the requirement about the local administrator password?
- Password Age Days set to 1
+ Post Authentication Actions, with a short Post Authentication Reset Delay
- Password Complexity set to the longest option
- Administrator Account Name set to a new account
! The post-authentication actions reset the password (and can sign the account out or restart the device) a set number of hours after the password is used. Password Age Days can't even go below 7 when the password is backed up to Microsoft Entra ID, and an age rotates the password on a schedule whether or not anyone used it.

@choice q09 | Configuration | 1
