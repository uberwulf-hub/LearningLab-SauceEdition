# Unit: u08 | 8. Windows updates | Updates

Windows gets two kinds of updates. **Quality updates** come every month (the cumulative update on the second Tuesday, "Patch Tuesday") and fix security holes and bugs. **Feature updates** move a PC to a new version of Windows, such as Windows 11 version 24H2. Intune manages both through **Windows Update for Business**: the PCs still download from Microsoft, but you decide when. This unit covers update rings, feature updates policies, expedited and driver updates, the reports, and what changed when Windows 10 reached its end of support.

## Lesson: l0801 | Windows Update for Business and update rings

Windows Update for Business is a set of Windows policies that tell the PC to **wait** before it installs an update (a deferral), and **how hard to push** the restart. Intune's main tool for it is the **update ring**: **Devices > Windows updates > Update rings > Create profile**.

### Update ring settings

- **Quality update deferral period**: 0 to 30 days after Microsoft releases a monthly update.
- **Feature update deferral period**: 0 to 365 days after a new Windows version is released.
- **Microsoft product updates** and **Windows drivers**: allow or block updates for other Microsoft products and drivers through Windows Update.
- **Upgrade Windows 10 devices to Latest Windows 11 release**: lets a ring move capable Windows 10 PCs to Windows 11.
- **Feature update uninstall period**: 2 to 60 days during which the user can go back to the previous version.
- **Automatic update behavior** and **active hours**: when Windows installs and restarts. Active hours (at most 18 hours a day) are the hours Windows won't restart.
- **Deadlines** (0 to 30 days) for quality and feature updates, plus a **grace period** (0 to 7 days): after the deadline, Windows restarts on its own outside active hours. The grace period gives a PC that was off for a while a few days before the forced restart.

### A ring on the device

A ring is a set of Policy CSP settings in the **Update** area, so the PC stores it under PolicyManager like any other profile:

```terminal
#setup portal:create ring name=Broad qualityDeferral=7 featureDeferral=30 qualityDeadline=3 featureDeadline=7 grace=2
#setup portal:assign ring Broad "Windows devices"
#setup portal:remote sync RB-LT-001
PS C:\Windows\system32> Get-ItemProperty HKLM:\SOFTWARE\Microsoft\PolicyManager\current\device\Update | Select-Object Defer*, Pause*

DeferQualityUpdatesPeriodInDays DeferFeatureUpdatesPeriodInDays PauseQualityUpdates PauseFeatureUpdates
------------------------------- ------------------------------- ------------------- -------------------
                              7                              30                   0                   0


PS C:\Windows\system32> Get-HotFix | Select-Object -Last 2

Source        Description      HotFixID      InstalledBy          InstalledOn
------        -----------      --------      -----------          -----------
RB-LT-001     Security Update  KB5050021     NT AUTHORITY\SYSTEM  1/20/2026 12:00:00 AM
RB-LT-001     Security Update  KB5051989     NT AUTHORITY\SYSTEM  2/11/2026 12:00:00 AM
```

> A device should be in **one** update ring. Two rings that target the same device both report a conflict.

## Lesson: l0802 | Rings in waves, pausing and going back

One ring for everyone means a bad update reaches everyone on the same day. The usual plan is **several rings**, each a little later than the one before:

- **Pilot**: IT and a few keen people, 0 days of deferral. They meet problems first.
- **Broad**: everyone else, for example 7 or 14 days later.
- Sometimes a **Critical** ring for PCs that must not break (tills, the CEO's laptop), later still.

Each device must land in exactly one ring. A simple way: assign Broad to all Windows devices and **exclude** the pilot device group, and assign Pilot to the pilot group. (Both are device groups, so the exclusion works.)

### Pausing and uninstalling

On an update ring's page you can **Pause** quality or feature updates when a problem shows up: devices in the ring install no new updates of that kind. A pause ends on its own after a fixed time (35 days in the current portal; it can be extended), so you don't forget it. **Resume** lifts it. **Uninstall** removes the latest quality or feature update from the ring's devices (for a feature update, only within the uninstall period).

> In Cert Lab a pause lasts until you resume it, and the ring page has no Uninstall button.

### Patch Tuesday and time

Monthly updates come out on the **second Tuesday** of each month. Cert Lab's clock starts on Monday 2 March 2026, so the March update appears on **Tuesday 10 March**. Devices check in about every 8 hours; **Skip time** in the portal moves the clock forward, and devices check in on their own as it passes.

? On which day does Microsoft usually release the monthly cumulative update?

! The monthly security update comes out on the second Tuesday, often called Patch Tuesday.

## Lesson: l0803 | Feature updates and Windows 11

An update ring with a feature deferral moves PCs to **the newest** Windows version once the deferral has passed. Often you want to choose the version yourself instead. A **feature updates policy** (**Devices > Windows updates > Feature updates > Create profile**) names one version, for example **Windows 11, version 24H2**:

- Devices below that version are offered it (as soon as possible, on a date you choose, or gradually).
- Devices on that version **stay there** until you change the policy, even when Microsoft releases a newer one. That is the way to hold a version.
- It is assigned to **device groups**. When you use a feature updates policy, set the ring's feature deferral to 0 so the two don't fight.
- It uses Microsoft's cloud update service (the Windows Update for Business deployment service, now part of Windows Autopatch): the devices must be Microsoft Entra joined or hybrid joined and send Windows diagnostic data, and the users need a licence that includes it (Windows Enterprise E3 or E5, Education A3 or A5, Windows VDA E3 or E5, or Microsoft 365 Business Premium).

### Windows 11's hardware requirements

Windows 11 needs, among other things, **TPM 2.0**, **UEFI with Secure Boot**, a supported 64-bit processor, 4 GB of memory and 64 GB of storage. A PC that doesn't meet them can't take the update. Windows Update doesn't offer Windows 11 to such a PC: it stays on Windows 10 22H2, the last Windows 10 version, and the policy's report shows that it can't take the update (Cert Lab shows **Not applicable**). (Older versions of the policy had an option to install the latest Windows 10 feature update instead; with Windows 10 out of support it is gone.) **RB-DT-007** (TPM 1.2) is such a PC.

### Windows 10's end of support

Windows 10 reached its **end of support on 14 October 2025**. Since then, Windows 10 22H2 gets no more monthly security updates unless the organisation buys **Extended Security Updates (ESU)**. In Cert Lab, the Windows 10 desktops are stuck on the October 2025 update; the way forward is a feature updates policy to Windows 11.

```terminal
#machine RB-DT-010
#setup portal:create group name="Win10 desktops" type=Security membership=Assigned members="RB-DT-010,RB-DT-007"
#setup portal:create featureUpdate name="Windows 11 24H2" version="Windows 11, version 24H2"
#setup portal:assign featureUpdate "Windows 11 24H2" "Win10 desktops"
PS C:\Windows\system32> Get-ComputerInfo -Property OsName, OsDisplayVersion, OsBuildNumber

OSDisplayVersion OsName                          OsBuildNumber
---------------- ------                          -------------
22H2             Microsoft Windows 10 Enterprise 19045
```

The same PC after a check-in:

```terminal

#setup portal:create group name="Win10 desktops" type=Security membership=Assigned members="RB-DT-010,RB-DT-007"
```

## Lesson: l0804 | Expedited and driver updates, reports, Autopatch and Delivery Optimization

### Expedited quality updates

Sometimes a security update can't wait for the ring's deferral, for example when an attack is already going round. A **quality updates policy** (**Devices > Windows updates > Quality updates > Create profile**) **expedites** one monthly update: "install it now on any device whose OS is older than this update", ignoring the ring's quality update deferral. You set how many days (0 to 2) Windows waits before it forces the restart. It is assigned to device groups and has the same requirements as feature updates policies (deployment service, licences, diagnostic data).

### Driver updates

A **driver updates policy** controls the drivers and firmware Windows Update offers: **Manually approve and deploy driver updates** (you review the list and approve each one) or **Automatically approve all recommended driver updates**, with an optional delay in days. The devices' update ring must not block Windows drivers.

### Reports and Windows diagnostic data

**Reports > Windows updates** shows feature update, quality update and expedited update status per device, and the errors. These reports need two things:

- In the tenant: **Tenant administration > Connectors and tokens > Windows data**: turn on **Enable features that require Windows diagnostic data in processor configuration**. (Cert Lab: Tenant administration > Settings > Connectors.)
- On the devices: Windows diagnostic data at **Required** level or higher (the settings catalog setting **System > Allow Telemetry**; Cert Lab's catalog still calls Required by its old name, **Basic**).

### Windows Autopatch and Delivery Optimization

- **Windows Autopatch** is a Microsoft service on top of Intune that runs the update rings for you: it splits devices into deployment rings (by default Test, Ring1, Ring2, Ring3 and Last), releases Windows, Microsoft 365 Apps, Edge and Teams updates in waves, and watches for problems. It comes with Windows Enterprise E3/E5, Education A3/A5 and Microsoft 365 Business Premium licences (Microsoft support requests only with E3 or higher). Know what it does; Cert Lab doesn't simulate it.
- **Delivery Optimization** lets PCs share update pieces with each other instead of all downloading from the internet. The **download mode** decides with whom: HTTP only, LAN (same network), Group, Internet, Simple, or Bypass. It is set with the Delivery Optimization template or the settings catalog (**Delivery Optimization > DO Download Mode**). Microsoft Connected Cache adds a local cache server.

### Phones and tablets

iPhones and iPads are updated with **iOS/iPadOS update policies** (supervised devices: install the latest update in a time window you choose); Android Enterprise devices have a **system update** setting in device restrictions (automatic, postponed, or a maintenance window). The exam asks about these only lightly.
