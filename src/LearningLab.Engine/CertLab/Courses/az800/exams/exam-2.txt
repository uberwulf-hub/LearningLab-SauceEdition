@task t01 | AD DS | 4 | DC1
DC2 sits in the branch office, whose subnet is **10.20.0.0/24**. Create the site **Branch** with that subnet, put the site in **DEFAULTIPSITELINK** and make that link replicate every **15 minutes**, then move **DC2** into the Branch site.
@check admin | the site, its subnet and the link
subnet["10.20.0.0/24"].site == Branch
sitelink["DEFAULTIPSITELINK"].sites has Branch
sitelink["DEFAULTIPSITELINK"].interval == 15
@check admin | DC2 is in Branch
dc["DC2"].site == Branch
@solution DC1
New-ADReplicationSite -Name Branch
New-ADReplicationSubnet -Name 10.20.0.0/24 -Site Branch
Set-ADReplicationSiteLink -Identity DEFAULTIPSITELINK -SitesIncluded @{Add="Branch"} -ReplicationFrequencyInMinutes 15
Move-ADDirectoryServer -Identity DC2 -Site Branch
@explain
New-ADReplicationSite doesn't put the new site in any site link (the console makes you pick one), and a site in no link gets no replication from other sites. The subnet tells clients and DCs which site an address belongs to; 15 minutes is the shortest interval a site link allows.
@endtask

@task t02 | Group Policy | 4 | admin
Every server must show the logon message title **Harborline servers {n}**. Create the GPO **Server banner {n}** with that setting, link it to the **Servers** OU, and make sure no GPO linked lower down can override it.
@check admin | the servers get the title
rsop(computer=FS1).setting["LogonTitle"].value == "Harborline servers {n}"
rsop(computer=SRV1).setting["LogonTitle"].winner == "Server banner {n}"
@check admin | the link is enforced
gpo["Server banner {n}"].enforced["Servers"] == Yes
@solution admin
gpo new "Server banner {n}"
gpo set "Server banner {n}" setting=LogonTitle state=Enabled value="Harborline servers {n}"
gpo link "Server banner {n}" Servers enforced=yes
@explain
The message title is under Computer Configuration > Policies > Windows Settings > Security Settings > Local Policies > Security Options. Enforcing the link makes its settings win over GPOs linked to child OUs and lets it pass Block Inheritance.
@endtask

@task t03 | Networking | 4 | SRV1
On SRV1, reserve **10.10.0.{ip}** in the scope **10.10.0.0** for the printer **PRN-HQ-01** (MAC address **00-1B-A9-4C-21-07**), and exclude **10.10.0.190-10.10.0.199** from the scope for static devices.
@check admin | the reservation and the exclusion
dhcp(SRV1).scope["10.10.0.0"].reservation["10.10.0.{ip}"].mac == 00-1B-A9-4C-21-07
dhcp(SRV1).scope["10.10.0.0"].exclusions has 10.10.0.190-10.10.0.199
@solution SRV1
Add-DhcpServerv4Reservation -ScopeId 10.10.0.0 -IPAddress 10.10.0.{ip} -ClientId 00-1B-A9-4C-21-07 -Name PRN-HQ-01
Add-DhcpServerv4ExclusionRange -ScopeId 10.10.0.0 -StartRange 10.10.0.190 -EndRange 10.10.0.199
@explain
A reservation ties an address to a client's MAC address (ClientId); an exclusion keeps addresses inside the range from being leased at all. The printer gets the reserved address at its next renewal.
@endtask

@task t04 | File and storage | 4 | FS1
On FS1, pool the four empty disks into a storage pool named **Pool{n}**, and create a **two-way mirror** volume named **Projects** on it, **100 GB**, formatted **ReFS**, as drive **P:**.
@check admin | the pool and the mirror
pool["Pool{n}"].disks == 4
vdisk["Projects"].resiliency == Mirror
vdisk["Projects"].copies == 2
@check admin | the volume
volume(FS1, P).fs == ReFS
@solution FS1
New-StoragePool -FriendlyName Pool{n} -StorageSubSystemFriendlyName "Windows Storage*" -PhysicalDisks (Get-PhysicalDisk -CanPool $true)
New-Volume -StoragePoolFriendlyName Pool{n} -FriendlyName Projects -ResiliencySettingName Mirror -NumberOfDataCopies 2 -Size 100GB -FileSystem ReFS -DriveLetter P
@explain
Get-PhysicalDisk -CanPool $true lists the disks that can join a pool (no partitions, not the system disk). New-Volume creates the virtual disk, partition and file system in one step; a two-way mirror needs two disks and uses twice its size in the pool.
@endtask

@task t05 | Hybrid identity | 4 | admin
Install Microsoft Entra Connect Sync on **SRV1** with **password hash synchronization**, syncing only the **Staff** OU. Before that, make **Bianca Cole** (bcole) sign in as **bcole@harborline.example**, the tenant's verified domain.
@check admin | sync is set up as asked
connect.server == SRV1
connect.signin == PHS
cloud.users !has svc-backup
@check admin | Bianca's cloud account uses the verified domain
cloud.user["bcole"].upn == bcole@harborline.example

upnsuffix add harborline.example
set user bcole upn=bcole@harborline.example
connect install server=SRV1 signin=PHS ous="OU=Staff,DC=corp,DC=example"
@explain
A user's UPN suffix must be a domain verified in the tenant; otherwise the cloud account gets the initial onmicrosoft domain. Add the suffix to the forest (Active Directory Domains and Trusts, or Set-ADForest -UPNSuffixes), change the users' UPNs, then sync. OU filtering keeps service accounts out.
@endtask

@task t06 | Virtualization | 3 | HV1
On HV1, create the generation 2 VM **WEB-{n}** with **2 GB** of startup memory, a new **40 GB** virtual hard disk and a connection to the switch **LAN**, then take a checkpoint named **Clean install**.
@check admin | the VM
vm["WEB-{n}"].generation == 2
vm["WEB-{n}"].switch == LAN
vm["WEB-{n}"].memorygb == 2
@check admin | the checkpoint
vm["WEB-{n}"].checkpoints has "Clean install"

@case cs2 | Brightwater Brewing
## Overview
Brightwater Brewing (a made-up company) brews and ships beer from a main brewery and runs three taprooms. It has 250 staff; two administrators look after the servers.

## Existing environment
The domain brightwater.example has two domain controllers at the brewery. File servers at the brewery hold the shared folders \\BW-FS1\Recipes and \\BW-FS1\Sales. Each taproom has one Windows Server 2022 server that is both a file server and a Hyper-V host, with a local copy of the sales folder that staff update by hand. The servers are managed with Remote Desktop. The company has an Azure subscription with a storage account but uses it only for backups.

## Requirements
- Staff everywhere use one path, \\brightwater.example\Shares\Sales, and reach the copy closest to them.
- The sales folders at the brewery and the taprooms stay identical automatically; a file changed in a taproom reaches the brewery.
- The taproom servers keep only recently used files locally; older files stay in Azure and come back when someone opens them.
- Administrators manage every server from a browser, including Hyper-V and storage, without Remote Desktop.
- Only the Brewers group may change files in \\BW-FS1\Recipes; everyone in the company may read them.

## Technical constraints
Use the existing Azure subscription. Don't add servers.
@endcase

@choice c1 | File and storage | 2 | case=cs2
What should you create for the single path requirement?
+ A domain-based DFS namespace with a folder Sales whose targets are the brewery's and the taprooms' shares
- A stand-alone DFS namespace on BW-FS1
- A DFS replication group with the sales folders
- A CNAME record named Shares that points to BW-FS1
! A domain-based namespace (\\domain\namespace) is hosted on several servers and, by default, refers clients to the folder target in their own site first. Replication is a separate job.

@multi c2 | File and storage | 2 | case=cs2
Which two components keep the sales folders identical and the taproom servers small? Each correct answer is part of the solution.
+ Azure File Sync with a sync group whose server endpoints are the sales folders, and cloud tiering on the taproom servers
+ A Storage Sync Service in the existing subscription with an Azure file share as the cloud endpoint
- DFS Replication with the taproom servers as read-only members
- Storage Replica between BW-FS1 and each taproom server
- Data Deduplication on the taproom servers' system volumes
! Azure File Sync keeps every server endpoint in a sync group in step through the Azure file share (the cloud endpoint), and cloud tiering keeps only recently used files on the server. Storage Replica copies whole volumes for disaster recovery, not files between several offices.

@yesno c4 | File and storage | 3 | case=cs2

Y Share permission Full Control for Authenticated Users, with the real limits set in NTFS, meets the requirement.
N NTFS Read for Domain Users and Modify for Brewers lets Brewers change files if the share gives Everyone only Read.

@choice c5 | File and storage | 2 | case=cs2
Which setting makes the taproom servers keep files from the last 30 days locally?
- A volume free space policy of 30 percent
+ A date policy that tiers files not accessed for 30 days
- Data Deduplication with a minimum file age of 30 days

@multi q07 | Group Policy | 1

+ GPOs linked to the domain are applied before GPOs linked to OUs
