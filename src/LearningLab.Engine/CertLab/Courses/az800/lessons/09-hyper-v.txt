# Unit: u09 | 9. Hyper-V virtual machines | Virtualization

**Hyper-V** is the hypervisor built into Windows Server: one physical server (the **host**) runs many virtual machines (**guests**), each with its own virtual hardware and operating system. This unit covers creating and sizing VMs, nested virtualization and virtual switches, and virtual hard disks and checkpoints, with a word on Hyper-V Replica and live migration. Harborline's host is HV1 (16 logical processors, 64 GB): `APP-OLD` runs an old order-tracking app, `WEB-TEST` is a test web server and `LAB-HOST` will run Hyper-V itself for the training team.

## Lesson: l0901 | Creating and configuring virtual machines

Install the role with `Install-WindowsFeature Hyper-V -IncludeManagementTools -Restart` (the processor needs virtualization extensions and SLAT). Manage it with Hyper-V Manager, Windows Admin Center (Virtual machines) or the **Hyper-V** PowerShell module. `New-VM` creates a VM:

### Generation 1 or 2

The **generation** is picked when the VM is created and **can never change**.

- **Generation 2**: UEFI firmware with **Secure Boot** and an optional virtual TPM, boots from a SCSI **VHDX** disk (up to 64 TB), PXE boot with the normal network adapter, faster start-up, no emulated legacy devices. Use it for every current Windows and Linux system.
- **Generation 1**: BIOS firmware, boots from an IDE disk (VHD or VHDX; the boot disk is limited to 2 TB), legacy network adapter for PXE. Only for old 32-bit operating systems or appliances that need it.

### Memory and processors

- **Static memory**: the VM always has its startup memory. Windows Server 2016 and later can change it while a supported guest runs.
- **Dynamic memory**: Hyper-V gives the VM memory as it needs it, between **Minimum** and **Maximum**, starting at **Startup**, with a **buffer** (spare %) and a **weight** (priority when memory runs short). Turning dynamic memory on or off needs the VM **off**; while it runs you can lower the minimum and raise the maximum.
- **Processors**: the virtual processor count (VM off to change it), **compatibility mode** (to live-migrate between hosts with different processor generations of the same maker), and **NUMA** settings for very large VMs.

### Integration services, enhanced session and versions

- **Integration services** connect the guest with the host: Heartbeat, Shutdown (clean shutdown from the host), Time Synchronization, Key-Value Pair Exchange, VSS (backups and production checkpoints) and **Guest Service Interface** (off by default; needed for `Copy-VMFile`). Windows guests get updates for them through Windows Update. `Enable-VMIntegrationService` switches one on.
- **Enhanced session mode** makes Hyper-V's console (VMConnect) an RDP connection over the VM bus: clipboard, local drives, audio, USB devices and printers, resizable screen, even before the guest has a network. It is **off by default on Windows Server**: `Set-VMHost -EnableEnhancedSessionMode $true`.
- The **configuration version** (Windows Server 2022 makes 10.0) decides which features a VM can use and which hosts can run it. A VM moved from an older host keeps its old version until you run `Update-VMVersion` with the VM off; that is one-way (the VM then can't go back to the older host).
- **Automatic start and stop actions** decide what happens when the host restarts (start if it was running, save state, shut down).

## Lesson: l0902 | Nested virtualization and virtual switches

### Nested virtualization

**Nested virtualization** lets a VM run Hyper-V itself (for labs, training, or containers with Hyper-V isolation inside a VM). On the host, with the VM **off**:

- `Set-VMProcessor -VMName LAB-HOST -ExposeVirtualizationExtensions $true` passes the processor's virtualization extensions to the VM.
- **Dynamic memory must be off** (give it enough static memory, at least 4 GB).
- **MAC address spoofing** on the VM's network adapter (`Set-VMNetworkAdapter -VMName LAB-HOST -MacAddressSpoofing On`), so the inner VMs' packets with their own MAC addresses get through; the other way is a NAT switch inside the VM.
- Supported on Intel VT-x and, since Windows Server 2022, AMD processors. Changing the memory of the running VM (runtime memory resize) doesn't work once nested virtualization is on.

```terminal
#machine HV1
PS C:\Windows\system32> Set-VMProcessor LAB-HOST -ExposeVirtualizationExtensions $true
Set-VMProcessor : Nested virtualization can't be turned on while the VM uses dynamic memory: turn dynamic memory off first (Set-VMMemory -DynamicMemoryEnabled $false).
At line:1 char:1
+ Set-VMProcessor LAB-HOST -ExposeVirtualizationExtensions $true
+ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
    + CategoryInfo          : InvalidOperation: (LAB-HOST:String) [Set-VMProcessor], VirtualizationException
    + FullyQualifiedErrorId : InvalidState,Microsoft.HyperV.PowerShell.Commands.SetVMProcessorCommand

PS C:\Windows\system32> Set-VMMemory LAB-HOST -DynamicMemoryEnabled $false
PS C:\Windows\system32> Set-VMProcessor LAB-HOST -ExposeVirtualizationExtensions $true

```

### Virtual switches

A **virtual switch** connects VMs' network adapters:

- **External**: bound to a physical network adapter; VMs reach the real network. **Allow management operating system to share this adapter** gives the host a virtual adapter on it too (HV1's switch LAN doesn't: the host has its own adapter). One physical adapter carries one external switch.
- **Internal**: VMs and the host talk to each other, nothing else. Add NAT on the host (`New-NetNat`) to give them internet access.
- **Private**: only the VMs on that host talk to each other; not even the host. Good for isolated test networks.

Other settings: **VLAN ID** per adapter (`Set-VMNetworkAdapterVlan`), bandwidth management, **SR-IOV**, and **Switch Embedded Teaming** (SET: teaming of several physical adapters inside the switch, `New-VMSwitch -NetAdapterName A, B -EnableEmbeddedTeaming $true`). `Connect-VMNetworkAdapter` moves a VM to another switch.

```terminal
#machine HV1
PS C:\Windows\system32> New-VMSwitch -Name Isolated -SwitchType Private

Name     SwitchType NetAdapterInterfaceDescription
----     ---------- ------------------------------
Isolated Private


PS C:\Windows\system32> Get-VMSwitch | Format-Table Name, SwitchType, AllowManagementOS

Name     SwitchType AllowManagementOS
----     ---------- -----------------
LAN      External   False
Isolated Private    False
```

@quiz

- External
+ Internal
- Private

? Nested virtualization is on, but the inner VMs can't reach the network through the outer VM's external switch. What is missing?

@end

## Lesson: l0903 | Virtual hard disks, checkpoints and moving VMs

### Virtual hard disks

- **VHD**: the old format, up to 2040 GB. **VHDX**: up to **64 TB**, resilient to power failures, 4 KB sectors; use it unless something old needs VHD. `Convert-VHD` converts (the disk must not be in use).
- **Fixed**: the whole size is allocated at once; best performance, used to be the advice for production. **Dynamic**: grows as data is written; with VHDX the performance is close to fixed. **Differencing**: holds only the changes against a read-only **parent** disk; many VMs can share one parent (lab images). Never change a parent: every child breaks.
- `New-VHD -Path ... -SizeBytes 60GB -Dynamic|-Fixed`, `New-VHD -Path child.vhdx -ParentPath base.vhdx -Differencing`, `Resize-VHD` (grow or shrink, online for SCSI-attached VHDX), `Add-VMHardDiskDrive`. Optimize-VHD compacts a dynamic disk. **Pass-through disks** (a physical disk given to a VM) are rarely used now.

```terminal
#machine HV1
PS C:\Windows\system32> New-VHD -Path 'D:\Hyper-V\Virtual Hard Disks\Base.vhdx' -SizeBytes 40GB -Dynamic | Out-Null
PS C:\Windows\system32> New-VHD -Path 'D:\Hyper-V\Virtual Hard Disks\Child.vhdx' -ParentPath 'D:\Hyper-V\Virtual Hard Disks\Base.vhdx' -Differencing | Format-List Path, VhdType, ParentPath

Path       : D:\Hyper-V\Virtual Hard Disks\Child.vhdx
VhdType    : Differencing
ParentPath : D:\Hyper-V\Virtual Hard Disks\Base.vhdx
```

### Checkpoints

A **checkpoint** saves a VM's state so you can go back to it. Behind it is a differencing disk (`.avhdx`), so a VM with many old checkpoints runs slower: delete them when done (the changes merge back).

- **Production** checkpoints (the default) use **VSS** inside Windows guests (or file system freeze in Linux): the data is consistent, like a backup, but memory isn't saved. Applying one leaves the VM **off**, and it starts like after a clean shutdown.
- **Standard** checkpoints save the memory and device state too: applying one returns the running programs exactly as they were. Not for production servers with databases or domain controllers (replication would go back in time).
- **ProductionOnly** fails instead of falling back to a standard checkpoint when VSS can't run; **Disabled** turns them off.
- Commands: `Checkpoint-VM -Name APP-OLD -SnapshotName 'Before patch'`, `Get-VMCheckpoint`, `Restore-VMCheckpoint`, `Remove-VMCheckpoint`. A checkpoint is **not a backup**: it lives on the same disk.

### Moving and protecting VMs

- **Live migration** moves a running VM to another host with no downtime: in a failover cluster, or between stand-alone hosts (**shared-nothing** live migration also copies the storage). Authentication by CredSSP (sign in on the source host) or Kerberos with constrained delegation. **Storage migration** moves only the files while the VM runs. Export / import copies a VM offline.
- **Hyper-V Replica** keeps an asynchronous copy of a VM on another host (every 30 seconds, 5 or 15 minutes), for disaster recovery; you fail over by hand. Azure Site Recovery can replicate to Azure.
