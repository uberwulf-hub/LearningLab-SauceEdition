SYNOPSIS: Creates a managed service account, normally a group managed service account (gMSA).
DESCRIPTION:
A gMSA is an account for services and scheduled tasks whose long, random password Windows changes by itself (every 30 days by default). Nobody needs to know it. The servers listed in -PrincipalsAllowedToRetrieveManagedPassword may fetch the password and run services as the account.
A gMSA needs a KDS root key in effect (Add-KdsRootKey); otherwise New-ADServiceAccount fails with "Key does not exist". -DNSHostName is required for a gMSA.
With -RestrictToSingleComputer you get an older standalone managed service account instead, tied to one computer.
New accounts go to the Managed Service Accounts container by default.
PARAMETER Name:
The account's name, such as gmsa-web (15 characters at most). Position 0.
PARAMETER DNSHostName:
A DNS name for the account, such as gmsa-web.corp.example.
PARAMETER PrincipalsAllowedToRetrieveManagedPassword:
The computers (or a group of computers) allowed to use it.
PARAMETER RestrictToSingleComputer:
Creates a standalone managed service account for one computer.
PARAMETER ManagedPasswordIntervalInDays:
How often the password changes; can only be set when the account is created.
PARAMETER Path:
Another container or OU.
PARAMETER Description:
A note about what it runs.
EXAMPLE: New-ADServiceAccount gmsa-web -DNSHostName gmsa-web.corp.example -PrincipalsAllowedToRetrieveManagedPassword SRV1$
A gMSA that the server SRV1 may use.
EXAMPLE: Install-ADServiceAccount gmsa-web
Then, on SRV1: installs it so services there can run as CORP\gmsa-web$.
RELATED: Add-KdsRootKey, Install-ADServiceAccount, Test-ADServiceAccount, Set-ADServiceAccount, Get-ADServiceAccount
