SYNOPSIS: Asks for a user name and password and returns them as a credential object.
DESCRIPTION:
Get-Credential asks the person at the keyboard for a user name and a password and returns a PSCredential object. The password is kept as a SecureString, so it is never shown.

Many commands take a credential with -Credential, for example Enter-PSSession, Invoke-Command and New-PSDrive. Store the credential in a variable once and reuse it.
PARAMETER Credential:
A user name to fill in, for example LAB\Administrator; only the password is asked. Passing an existing PSCredential returns it unchanged.
PARAMETER UserName:
The user name to fill in.
PARAMETER Message:
The text shown above the question.
PARAMETER Title:
The title of the request.
EXAMPLE: $cred = Get-Credential LAB\Administrator
Asks for the password of LAB\Administrator and keeps the credential in $cred.
EXAMPLE: Invoke-Command -ComputerName WIN-SRV1 -Credential $cred -ScriptBlock { hostname }
Uses the credential to run a command on another computer.
EXAMPLE: Get-Credential -UserName 'LAB\alice' -Message 'Account for the backup job'
Asks with your own message.
NOTES:
Windows PowerShell 5.1 normally shows a sign-in dialog box; Cert Lab asks in the console, like PowerShell 7 does.
In a session that cannot ask questions (non-interactive), Get-Credential fails.
Never write passwords into scripts. For scheduled jobs, save the password with ConvertFrom-SecureString as the account that will use it.
RELATED: ConvertTo-SecureString, ConvertFrom-SecureString, Invoke-Command, Enter-PSSession
