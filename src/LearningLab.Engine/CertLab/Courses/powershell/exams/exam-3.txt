@task t01 | Scripting | 8 | WIN-SRV1
Write the script `C:\Scripts\Get-Payroll.ps1` with a **mandatory** parameter `-Department` that accepts **only** `Engineering`, `Research` or `IT` (anything else must be refused by PowerShell before the script runs), and a switch `-Average`. It outputs **only a number**: the total of the Salary column of `C:\LabFiles\employees.csv` for that department, or with `-Average` the average salary rounded to a whole number.
@check WIN-SRV1 | the total for {dept}
$t = 0; Import-Csv C:\LabFiles\employees.csv | Where-Object Department -eq '{dept}' | ForEach-Object { $t += [int]$_.Salary }; (& C:\Scripts\Get-Payroll.ps1 -Department {dept}) -eq $t
@check WIN-SRV1 | -Average gives the rounded average
$r = @(Import-Csv C:\LabFiles\employees.csv | Where-Object Department -eq '{dept}'); $t = 0; $r | ForEach-Object { $t += [int]$_.Salary }; (& C:\Scripts\Get-Payroll.ps1 -Department {dept} -Average) -eq [math]::Round($t / $r.Count)
@check WIN-SRV1 | another department name is refused by parameter validation
try { & C:\Scripts\Get-Payroll.ps1 -Department Sales -ErrorAction Stop | Out-Null; $false } catch { $_.FullyQualifiedErrorId -like 'ParameterArgumentValidationError*' }
@solution WIN-SRV1
New-Item -ItemType Directory -Path C:\Scripts -Force | Out-Null
Set-Content -Path C:\Scripts\Get-Payroll.ps1 -Value @'
param([Parameter(Mandatory)][ValidateSet('Engineering', 'Research', 'IT')][string]$Department, [switch]$Average)
$m = Import-Csv C:\LabFiles\employees.csv | Where-Object Department -eq $Department | Measure-Object -Property Salary -Sum -Average
if ($Average) { [math]::Round($m.Average) } else { $m.Sum }
'@
@explain
[ValidateSet()] makes PowerShell check the value while binding parameters, so a wrong name fails with a clear message before any line of the script runs. Measure-Object converts the text from the CSV into numbers for -Sum and -Average.
@endtask

@task t02 | Errors | 8 | WIN-SRV1
Write the script `C:\Scripts\Measure-Files.ps1`. It takes a mandatory parameter `-Path` that accepts **several** paths. For each path that is a file it outputs the file's size in bytes (a number). For a path that does not exist it writes a **non-terminating** error with the message `No file: <path>` and goes on with the next path. Callers must be able to hide or collect these errors with the common parameters `-ErrorAction` and `-ErrorVariable`.
@check WIN-SRV1 | it keeps going after a missing file
$r = & C:\Scripts\Measure-Files.ps1 -Path C:\LabFiles\notes.txt, C:\LabFiles\{missing}.txt, C:\LabFiles\servers.txt -ErrorAction SilentlyContinue; @($r).Count -eq 2 -and $r[1] -eq (Get-Item C:\LabFiles\servers.txt).Length
@check WIN-SRV1 | the error message, collected with -ErrorVariable
$null = & C:\Scripts\Measure-Files.ps1 -Path C:\LabFiles\{missing}.txt -ErrorAction SilentlyContinue -ErrorVariable ev; @($ev).Count -eq 1 -and "$($ev[0])" -eq 'No file: C:\LabFiles\{missing}.txt'
@solution WIN-SRV1
New-Item -ItemType Directory -Path C:\Scripts -Force | Out-Null
Set-Content -Path C:\Scripts\Measure-Files.ps1 -Value @'
[CmdletBinding()]
param([Parameter(Mandatory)][string[]]$Path)
foreach ($p in $Path) {
    if (Test-Path -LiteralPath $p -PathType Leaf) { (Get-Item -LiteralPath $p).Length }
    else { Write-Error "No file: $p" }
}
'@
@explain
Write-Error reports a non-terminating error: it is recorded and shown, and the script carries on. [CmdletBinding()] gives the script the common parameters, so -ErrorAction SilentlyContinue hides the errors and -ErrorVariable collects them. throw would stop at the first missing file.
@endtask

@task t03 | Modules | 8 | WIN-SRV1
Make the alias `{alias}` for `Get-ChildItem` available in **every** PowerShell session on WIN-SRV1, for **all users** and in every host program. Use the right profile file.

@endtask

@task t05 | Administration | 8 | WIN-SRV1
Register the event source `{src}` in the **Application** log, and write one **Warning** event from it with the event ID **{id}** and the message `Backup was skipped`.
@check WIN-SRV1 | the warning is in the Application log
$e = @(Get-WinEvent -FilterHashtable @{ LogName = 'Application'; ProviderName = '{src}'; Id = {id} } -ErrorAction SilentlyContinue); $e.Count -ge 1 -and $e[0].Message -eq 'Backup was skipped' -and $e[0].Level -eq 3

@task t07 | Security | 8 | WIN-SRV1
Save the password `{pw}` of the account `LAB\{acct}` in `C:\Secure\{acct}.txt` so that a script running as **you** can read it back as a SecureString later, without the password ever being stored as plain text.
@check WIN-SRV1 | the file does not contain the password as text
(Test-Path C:\Secure\{acct}.txt) -and -not ((Get-Content C:\Secure\{acct}.txt -Raw).Contains('{pw}'))
@check WIN-SRV1 | it reads back as the right password
$s = Get-Content C:\Secure\{acct}.txt | ConvertTo-SecureString; (New-Object System.Management.Automation.PSCredential('LAB\{acct}', $s)).GetNetworkCredential().Password -eq '{pw}'
@solution WIN-SRV1

@choice c04 | Language | 4

@choice c05 | Remoting | 4
`$s = Invoke-Command -ComputerName WIN-CL1 -ScriptBlock { Get-Service Spooler }` works, but `$s.Stop()` fails. Why?
- Invoke-Command returns only text
- Services cannot be stopped on another computer
+ The object that came back is a deserialized copy: it has the properties but not the methods
- $s holds the job that ran the command, not the service
! Results travel back as XML and become Deserialized objects with their property values only. Stop the service inside the script block instead, for example Invoke-Command ... { Stop-Service Spooler }.

@choice c06 | Security | 4
Group Policy sets the execution policy to `AllSigned` for the computer (the MachinePolicy scope), and the LocalMachine scope says `Unrestricted`. Which policy applies to a user who has set nothing?
+ `AllSigned`
- `Unrestricted`
- `RemoteSigned`, the default for Windows Server
- `Undefined`, because the two settings disagree
! Scopes are read in this order: MachinePolicy, UserPolicy, Process, CurrentUser, LocalMachine. The first one that is not Undefined wins, so Group Policy beats everything you set yourself.
