# Exam: exam-2 | Practice exam 2 | 120
Two machines: WIN-SRV1 (Windows Server 2022) and WIN-CL1 (Windows 11), both with sample files in C:\LabFiles. You are the administrator on both. Hands-on work must still be there after a restart: the grader restarts both machines and checks them in a new PowerShell session. Questions: pick one answer.

@vars
min = 80000-100000
report = HighEarners | TopPay | SalaryCheck
corp = Contoso | Adatum | Tailspin
mode = Modern | Compact | Secure
mod = DeskKit | AdminBox | ToolBelt
noun = DiskReport | PatchState | LogSummary
ver = 1.4.0 | 2.0.1 | 3.2.5
svc = Spooler | WSearch | Themes
port = 8100-8999
rule = LabApp | InventoryWeb | HelpDeskApi

key = AppLimits | Quotas | Throttle
limit = 20-90
dsvc = BITS | MSiSCSI
@endvars

@task t01 | Pipeline | 8 | WIN-SRV1
From `C:\LabFiles\employees.csv`, save the employees who earn **more than {min}** to `C:\Reports\{report}.csv`, sorted by salary from **highest to lowest**. The file has exactly two columns, `Name` and `Salary`, and no `#TYPE` line.
@check WIN-SRV1 | the right people in the right order
$want = Import-Csv C:\LabFiles\employees.csv | Where-Object { [int]$_.Salary -gt {min} } | Sort-Object { [int]$_.Salary } -Descending; $got = Import-Csv C:\Reports\{report}.csv; (@($got).Name -join ',') -eq (@($want).Name -join ',')
@check WIN-SRV1 | only the columns Name and Salary, no #TYPE line
(Get-Content C:\Reports\{report}.csv -TotalCount 1) -eq '"Name","Salary"'
@solution WIN-SRV1
New-Item -ItemType Directory -Path C:\Reports -Force | Out-Null
Import-Csv C:\LabFiles\employees.csv | Where-Object { [int]$_.Salary -gt {min} } | Sort-Object { [int]$_.Salary } -Descending | Select-Object Name, Salary | Export-Csv C:\Reports\{report}.csv -NoTypeInformation
@explain
Values from a CSV file are text, so the filter and the sort cast Salary to [int]; sorted as text from highest to lowest, "79000" would come before "124000". Select-Object picks the columns, and -NoTypeInformation leaves out the #TYPE line that Export-Csv writes in Windows PowerShell 5.1.
@endtask

@task t02 | Output | 8 | WIN-CL1
On **WIN-CL1**, save the local user accounts to `C:\Reports\users.csv` with the columns `Name`, `Enabled` and `Description`, separated by **semicolons** (`;`) instead of commas, and without a `#TYPE` line.
@check WIN-CL1 | the header uses semicolons
(Get-Content C:\Reports\users.csv -TotalCount 1) -eq '"Name";"Enabled";"Description"'
@check WIN-CL1 | one row per local user
@(Import-Csv C:\Reports\users.csv -Delimiter ';').Count -eq @(Get-LocalUser).Count
@solution WIN-CL1
New-Item -ItemType Directory -Path C:\Reports -Force | Out-Null
Get-LocalUser | Select-Object Name, Enabled, Description | Export-Csv C:\Reports\users.csv -Delimiter ';' -NoTypeInformation
@explain
Export-Csv -Delimiter picks the separator (Import-Csv needs the same -Delimiter to read it back). -UseCulture would use the list separator of the computer's region settings instead.
@endtask

New-ItemProperty -Path 'HKLM:\SOFTWARE\{corp}\Settings' -Name Mode -Value Classic -PropertyType String | Out-Null

@task t03 | Providers | 8 | WIN-SRV1
The registry key `HKLM:\SOFTWARE\{corp}\Settings` holds the values `Mode`, `Legacy` and `Port`. First copy the whole key, with its values, to `HKLM:\SOFTWARE\{corp}\Backup`. Then, in `Settings` only, change `Mode` to `{mode}` and delete the value `Legacy`.
@check WIN-SRV1 | the backup keeps the old values
$b = Get-ItemProperty -Path 'HKLM:\SOFTWARE\{corp}\Backup'; $b.Mode -eq 'Classic' -and $b.Legacy -eq 1 -and $b.Port -eq 8080
@check WIN-SRV1 | Settings has the new Mode and no Legacy
$s = Get-Item -Path 'HKLM:\SOFTWARE\{corp}\Settings'; $s.GetValue('Mode') -eq '{mode}' -and ($s.Property -notcontains 'Legacy') -and $s.GetValue('Port') -eq 8080
@solution WIN-SRV1
Copy-Item -Path 'HKLM:\SOFTWARE\{corp}\Settings' -Destination 'HKLM:\SOFTWARE\{corp}\Backup'
Set-ItemProperty -Path 'HKLM:\SOFTWARE\{corp}\Settings' -Name Mode -Value '{mode}'
Remove-ItemProperty -Path 'HKLM:\SOFTWARE\{corp}\Settings' -Name Legacy
@explain
In the registry, keys are items (Copy-Item copies a key with its values) and values are item properties: Set-ItemProperty changes one, Remove-ItemProperty deletes one. Remove-Item would delete the whole key.
@endtask

@task t04 | Modules | 8 | WIN-SRV1
Create the module `{mod}`, version **{ver}**, so that every user's PowerShell finds it. Its `.psm1` file defines two functions: `Get-{noun}`, which outputs the text `{noun} OK`, and a helper `Format-Line`. Use a **module manifest** so that only `Get-{noun}` is exported.
@check WIN-SRV1 | the module is found with version {ver}
"$((Get-Module -ListAvailable -Name {mod}).Version)" -eq '{ver}'
@check WIN-SRV1 | Get-{noun} works and comes from {mod}
(Get-{noun}) -eq '{noun} OK' -and (Get-Command Get-{noun}).Source -eq '{mod}'
@check WIN-SRV1 | the helper is not exported
Import-Module {mod}; -not (Get-Command Format-Line -ErrorAction SilentlyContinue)
@solution WIN-SRV1
$dir = 'C:\Program Files\WindowsPowerShell\Modules\{mod}'
New-Item -ItemType Directory -Path $dir -Force | Out-Null
Set-Content -Path "$dir\{mod}.psm1" -Value "function Get-{noun} { '{noun} OK' }", 'function Format-Line { param($Text) $Text.Trim() }'
New-ModuleManifest -Path "$dir\{mod}.psd1" -RootModule {mod}.psm1 -ModuleVersion {ver} -FunctionsToExport Get-{noun}
@explain
The manifest (.psd1) gives the module its version and lists what it exports; RootModule points at the .psm1. A folder under C:\Program Files\WindowsPowerShell\Modules is in every user's $env:PSModulePath.
@endtask

@task t05 | Administration | 8 | WIN-CL1
On **WIN-CL1**, stop the service `{svc}` and make sure it **cannot start** again, also after a restart.
@check WIN-CL1 | the service is disabled
"$((Get-Service -Name {svc}).StartType)" -eq 'Disabled'
@check WIN-CL1 | the service is stopped
"$((Get-Service -Name {svc}).Status)" -eq 'Stopped'
@solution WIN-CL1
Stop-Service -Name {svc} -Force
Set-Service -Name {svc} -StartupType Disabled
@explain
Stop-Service only stops it until the next start; the start type Disabled keeps it from starting at boot and refuses Start-Service. -Force also stops services that others depend on.
@endtask

@task t06 | Administration | 8 | WIN-SRV1
Create a Windows firewall rule named `{rule}` (both its Name and DisplayName) that **allows inbound TCP** traffic to local port **{port}** on all profiles.
@check WIN-SRV1 | the rule exists, is enabled and allows inbound traffic
$r = Get-NetFirewallRule -Name '{rule}' -ErrorAction SilentlyContinue; $r -and "$($r.Enabled)" -eq 'True' -and "$($r.Direction)" -eq 'Inbound' -and "$($r.Action)" -eq 'Allow' -and $r.DisplayName -eq '{rule}'
@check WIN-SRV1 | it is for TCP port {port}
$f = Get-NetFirewallRule -Name '{rule}' | Get-NetFirewallPortFilter; "$($f.Protocol)" -eq 'TCP' -and "$($f.LocalPort)" -eq '{port}'
@solution WIN-SRV1
New-NetFirewallRule -Name '{rule}' -DisplayName '{rule}' -Direction Inbound -Protocol TCP -LocalPort {port} -Action Allow
@explain
New-NetFirewallRule saves the rule in the computer's firewall settings, so it lasts across restarts. Without -Profile the rule applies to Any profile. The port and protocol live in the rule's port filter (Get-NetFirewallPortFilter).
@endtask

@task t07 | Remoting | 8 | WIN-SRV1
Remoting is turned on on both machines. From **WIN-SRV1**, use **one** `Invoke-Command` to ask both WIN-SRV1 and WIN-CL1 for the `Caption` and `Version` of their operating system (`Win32_OperatingSystem`), and save the answers to `C:\Reports\os.csv` on WIN-SRV1 with the columns `PSComputerName`, `Caption` and `Version`.
@check WIN-SRV1 | one row per computer
$rows = @(Import-Csv C:\Reports\os.csv); $rows.Count -eq 2 -and (($rows.PSComputerName | Sort-Object) -join ',') -eq 'WIN-CL1,WIN-SRV1'
@check WIN-SRV1 | WIN-CL1's row says Windows 11
((Import-Csv C:\Reports\os.csv) | Where-Object PSComputerName -eq 'WIN-CL1').Caption -match 'Windows 11'
@solution WIN-SRV1
New-Item -ItemType Directory -Path C:\Reports -Force | Out-Null
Invoke-Command -ComputerName WIN-SRV1, WIN-CL1 -ScriptBlock { Get-CimInstance -ClassName Win32_OperatingSystem | Select-Object Caption, Version } | Select-Object PSComputerName, Caption, Version | Export-Csv C:\Reports\os.csv -NoTypeInformation
@explain
Invoke-Command runs the script block on every computer at once and adds PSComputerName to each object that comes back, so you can tell the answers apart. Export-Csv runs locally, so the file is written on WIN-SRV1.
@endtask

@task t08 | Security | 8 | WIN-CL1
On **WIN-CL1**, the script `C:\Users\Administrator\Downloads\{tool}.ps1` was downloaded from the internet. Make it run for **you** (the Administrator): set the execution policy **RemoteSigned for your account only** (not for the whole machine, and not Unrestricted or Bypass), and mark the file as safe so that RemoteSigned lets it run.
@check WIN-CL1 | CurrentUser is RemoteSigned and LocalMachine is unchanged
"$(Get-ExecutionPolicy -Scope CurrentUser)" -eq 'RemoteSigned' -and @('Undefined', 'Restricted') -contains "$(Get-ExecutionPolicy -Scope LocalMachine)"
@check WIN-CL1 | the script runs
(& C:\Users\Administrator\Downloads\{tool}.ps1) -eq '{tool} finished'
@solution WIN-CL1
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser -Force
Unblock-File -Path C:\Users\Administrator\Downloads\{tool}.ps1
@explain
The CurrentUser scope beats LocalMachine for that one account. RemoteSigned still refuses an unsigned file marked as downloaded (its Zone.Identifier stream); Unblock-File removes that mark. Only do this for scripts you have read and trust.
@endtask

@task t09 | DSC | 8 | WIN-SRV1
Use **DSC** on WIN-SRV1 to make sure that the registry value `HKLM:\SOFTWARE\{key}\MaxJobs` is the **DWORD** `{limit}`, and that the service `{dsvc}` is **running** and starts **automatically**. Compile the configuration into `C:\DscConfigs\{key}` and apply it.
@check WIN-SRV1 | MaxJobs is the DWORD {limit}
$k = Get-Item 'HKLM:\SOFTWARE\{key}'; $k.GetValue('MaxJobs') -eq {limit} -and "$($k.GetValueKind('MaxJobs'))" -eq 'DWord'
@check WIN-SRV1 | {dsvc} runs and starts automatically
$s = Get-Service -Name {dsvc}; "$($s.Status)" -eq 'Running' -and "$($s.StartType)" -eq 'Automatic'
@check WIN-SRV1 | compiled to a MOF and in the desired state
(Test-Path 'C:\DscConfigs\{key}\WIN-SRV1.mof') -and (Test-DscConfiguration)
@solution WIN-SRV1
Configuration {key}Cfg { Import-DscResource -ModuleName PSDesiredStateConfiguration; Node 'WIN-SRV1' { Registry Jobs { Key = 'HKLM:\SOFTWARE\{key}'; ValueName = 'MaxJobs'; ValueData = '{limit}'; ValueType = 'Dword'; Ensure = 'Present' }; Service Svc { Name = '{dsvc}'; State = 'Running'; StartupType = 'Automatic' } } }
{key}Cfg -OutputPath 'C:\DscConfigs\{key}'
Start-DscConfiguration -Path 'C:\DscConfigs\{key}' -Wait
@explain
The Registry resource takes ValueData as text and ValueType picks the registry type (String is the default). The Service resource sets both the state and the start type. Test-DscConfiguration returns True when nothing has drifted.
@endtask

@choice c01 | Help | 4
Which command shows just the examples from the help of `Get-ChildItem`?
- `Get-Help Get-ChildItem -Full`
+ `Get-Help Get-ChildItem -Examples`
- `Get-Command Get-ChildItem -Syntax`

@choice c04 | Output | 4
Why does `Get-Service | Format-Table Name, Status | Export-Csv C:\Reports\s.csv` not give a useful CSV file?
- Export-Csv cannot export services
- Format-Table only works at the end of a line, so the command fails

! Format-* cmdlets output instructions for drawing a table. Pick columns with Select-Object instead, and keep Format-* for the very end of a line that shows output on screen.

@choice c05 | Errors | 4
What does this print?
    try { 'a'; throw 'boom'; 'b' } catch { "c:$_" } finally { 'd' }
+ `a / c:boom / d`
- `a / b / c:boom / d`
- `c:boom / d`
- `a / c:boom`
! throw stops the try block at once, so 'b' never runs. In catch, $_ is the error, which shows as its message. finally always runs last.
