answer: 10.20.30.{{HOST}}
var: HOST = num:20-99
var: C2 = ip
var: N = num:40-70

@intro
~/conn.log is a connection log from the office firewall: time, inside address, outside
address, port and bytes. People browse all over the place, but malware "beacons": it
calls the same server again and again, on a timer. Which inside address is beaconing?

@setup
log=/home/player/conn.log
: > $log
i=0
for dst in 192.0.2.80 192.0.2.81 198.51.100.5 203.0.113.70 192.0.2.99 198.51.100.150; do
  for src in 10.20.30.11 10.20.30.12 10.20.30.14 10.20.30.17; do
    i=$((i+1))
    printf '2026-03-01T%02d:%02d:%02d %s %s 443 %d\n' $((9+i%8)) $((i*13%60)) $((i*7%60)) $src $dst $((1000+i*311)) >> $log
  done
done
j=0
while [ $j -lt {{N}} ]; do
  printf '2026-03-01T%02d:%02d:00 10.20.30.{{HOST}} {{C2}} 8443 312\n' $((10+j/60)) $((j%60)) >> $log
  j=$((j+1))
done
sort $log -o $log
chown player: $log

@solution
head -5 conn.log
awk '{print $2, $3}' conn.log | sort | uniq -c | sort -rn | head -3

@walkthrough
Count how often each inside/outside pair appears:

    awk '{print $2, $3}' conn.log | sort | uniq -c | sort -rn | head -3

One pair stands far above the others: 10.20.30.{{HOST}} -> {{C2}}, {{N}} times, every
minute on the minute, always 312 bytes, on port 8443. Regular timing and identical sizes
are what beacons look like; people never browse that evenly.

@hint 15
