1. Look around. nmap -sn 10.10.1.0/24 sweeps the network: besides scout (10.10.1.5) one host answers,
   10.10.1.20. nmap -sV 10.10.1.20 shows ssh (22) and FTP (21, vsftpd).

2. Anonymous FTP. ftp 10.10.1.20, user anonymous, any password. The pub folder holds new-staff.txt, a
   note from IT with Dana's temporary password.

3. Foothold. ssh dana@10.10.1.20 with that password works: Dana never changed it. Her flag is in
   /home/dana/flag.txt.

4. Privilege escalation. sudo -l shows Dana may run /usr/bin/find as root without a password. find runs
   a program for each file it finds (-exec), so sudo find /root -name flag.txt -exec cat {} \; prints
   root's flag as root.

How to fix it: turn off anonymous FTP (or keep nothing private in it), make new passwords expire at the
first sign-in (chage -d 0 dana), and never give sudo rights to programs that can start other programs
(find, vim, less, awk...): allow the exact command that is needed instead.
